# 作曲・編曲学習ツール — 詳細仕様 v0.3

- 状態: 実装前設計案（本書の固定事項は v0.3 の採用案。実装・動作確認済みではない）
- 想定環境: Windows 11 / ローカルデスクトップ / キーボード・マウスのみで操作可能
- 対象: 音楽理論・作曲経験がほぼない利用者
- 最終目的: 特定ジャンルのテンプレートに頼らず、自分で作曲・編曲の判断ができること
- 初期実装目標: 既存または付属の8小節の旋律を、ベース・コード伴奏・ドラムと組み合わせて完成させ、別の素材で再現できる

## A. 基本原則・非目標

1. 聴く → 操作 → 聴き比べる → 言語化 → 別素材で再実施を一組の学習単位とする。
2. 理論は説明の手段。自由制作で理論外の音を禁止しない。
3. 客観条件の合否と音楽表現の善し悪しを分離する。
4. 提案は段階式。AIが自動的に完成曲を代筆しない。
5. レッスンは再編集可能な通常の楽曲プロジェクトを操作する。専用の使い捨てエディタは作らない。
6. 初期は音符・MIDI中心。オーディオ録音、多数のVST、複雑なミキサー、生成AI作曲をMVPに含めない。
7. ただし最初から和音、ドラム、複数楽器を表現できるデータ構造にする。

## C. 縦方向の実装課題: L-U06-01「初めての8小節編曲」

### C1. 教材の固定条件

- テンポ: 96 BPM、拍子: 4/4、キー: Cメジャー
- 長さ: 8小節（PPQ=480では合計15,360 ticks）
- コード進行: C | Am | F | G | C | Am | F | C
- ベース、コード伴奏、ドラム、主旋律の4役割を使用する。
- U05までの学習者は自作品の8小節を教材へ持ち込める。即時デモや未作成者には以下の付属旋律を提供する。
- 提示するコード進行や伴奏方法は練習素材であり、自由制作での唯一の正解ではない。

### C2. 付属旋律（音価 q=四分、h=二分。各小節4拍）

| 小節 | コード | 旋律 |
|---|---|---|
| 1 | C | E4 q / G4 q / E4 q / C4 q |
| 2 | Am | E4 q / A4 q / C5 q / A4 q |
| 3 | F | F4 q / A4 q / C5 q / A4 q |
| 4 | G | G4 q / B4 q / D5 q / B4 q |
| 5 | C | E4 q / G4 q / C5 q / G4 q |
| 6 | Am | E4 q / A4 q / C5 q / A4 q |
| 7 | F | F4 q / A4 q / C5 q / A4 q |
| 8 | C | G4 q / E4 q / C4 h |

意図: まず旋律と伴奏の役割を切り分ける。全音がコード構成音になる単純な素材にして、非和声音の説明は別のレッスンに回す。

### C3. ステップ別の画面・操作・自動判定

| Step | 初期表示 | ユーザーの必須操作 | 進行条件（課題モード限定） | 解説ポイント |
|---|---|---|---|---|
| S0 開始 | 付属旋律を読込。課題概要と4役割表示 | 「始める」押下、音声初期化 | 音声エンジンの開始に成功 | 音が鳴る仕組みと4役割 |
| S1 旋律の観察 | メロディのみ再生可能 | 8小節を再生・観察し、気付いた点を1つ選択 | 8小節の再生完了と選択回答（初回は聞こえたか確認） | 主旋律と伴奏の区別 |
| S2 コード | コードトラック。8小節に候補表示 | 規定の進行を並べる。任意に比較試聴 | 8小節に指定コードが配置 | コードの音構成と響き |
| S3 ベース | 低音用ピアノロール。必要に応じルート音ヒント | 各小節にベース音を1つ以上置く | 8小節にルート音が各1つ（本課題のみ） | 低音で和声の土台を作る |
| S4 伴奏 | 和音入力パネル、ボイシング試聴 | 各小節に三和音を配置 | 8小節で指定コードの構成音を確認 | 同じ和音を別の音域で鳴らす |
| S5 ドラム | 16ステップグリッド×1小節。拡張・複製可 | キック、スネア、ハイハットを配置・複製 | 基本パターンの配置、8小節に展開 | 拍・裏拍・強拍 |
| S6 分解して聴く | 全体と各トラックの再生切替 | 全体、ベース抜き、ドラム抜きを比較 | 指定した3パターンを実際に試聴 | 各役割が何を担うか |
| S7 意図して変更 | 保存スナップショットAと現在のB | 伴奏の音域・リズム・音量などを1項目変更しA/B比較 | 差分が1つ以上存在、比較実施、自己説明を記録 | 変更の根拠を言葉にする |
| S8 転移課題 | 4小節の別素材、ヒント原則非表示 | 4パートのうち少なくとも3役割を独力で作る | 制約満了・ヒント使用量・回答記録 | 別素材でも応用できるか |

### C4. 最初のベース・伴奏・ドラムの手本

- ベースの例: C2 | A1 | F1 | G1 | C2 | A1 | F1 | C2 。各小節の1拍目に全音符を1つ置く。最初は分かりやすくルートだけ。後でオクターブ・経過音・休符を試す。
- コード伴奏の例: 各小節の頭に三和音を置いて4拍保持。基本形、転回形、音域の変更はS4で聴き比べる。
- ドラムの初期パターン: 4/4の1小節16ステップでキック0・8、スネア4・12、クローズドハイハット0・2・4・6・8・10・12・14。これを各小節に複製し、後から差分を編集可能。
- General MIDI出力では例としてキック=36、スネア=38、クローズドハイハット=42を使い、通常はドラム用のMIDIチャンネル10（内部0-basedでは9）を指定する。
- ドラム無しの編曲も音楽的には有効。上のチェックは「ドラムを学ぶ」という本課題の要件に限る。

### C5. 転移課題の設定

- キーCのまま4小節で別進行（C | F | Am | G）と別の短い旋律を提供する。
- 手本の音符・トラック配置は渡さない。用語説明は開ける。
- ベース、伴奏、ドラムのうち3役割を独力で配置できるか確認する。
- 既習技能の修了判定は複数回の独立課題の記録で行い、一度の完成で技能全般を保証しない。
- 音楽的な工夫や創作性に「正解ラベル」は付けない。

## D. 画面構成と遷移

### D1. グローバルナビゲーション

- ホーム: 続きから再開、最近の作品、推奨復習
- 学習: ユニットと課題、進捗、苦手分野
- 自由制作: 新規作成または既存作品から開始
- 作品: プロジェクト管理、名前変更、MIDI出力
- 設定: オーディオデバイス、音源、言語、キー操作、バックアップ

### D2. エディタワークスペース

画面は単一エディタを共有し、課題モードでは段階に応じて操作要素を段階的に公開する。

- 上部（常時）: 再生/停止、ループ、BPM、拍子、小節位置、保存状態、学習/自由切替
- 左（約260px、折りたたみ可）: 現在の課題、やること、完了条件、ヒントを表示
- 中央（残り領域・最小600px）: トラックとクリップ。下段にピアノロールまたはドラムグリッド
- 右（約260px、折りたたみ可）: 選択音符/楽器の属性、コード情報、トラックの役割の説明
- 下部（表示切替）: A/B比較、周波数ではなくまず音符・音域・密度の可視化
- 小画面では左右をドロワー化。中央のピアノロールを犠牲にしない。

### D3. 最低限の操作規約

- 左クリック: 音符追加。選択ツール利用中は対象選択
- ドラッグ: 音符移動。右端ドラッグ: 長さ変更
- 右クリックまたはDelete: 削除
- Ctrl+Z/Ctrl+Y: Undo/Redo（楽曲編集に加えクリップ移動なども対象）
- Space: 再生・停止
- ホイール: 縦スクロール。Ctrl+ホイール: 拡大縮小（操作対象によって調整可能）
- M/S: トラックのミュート/ソロを視覚的に表示、誤操作を防ぐ
- チュートリアルで不要な要素は隠すが、何を操作できないかと解除方法は明示する
- 音符のドラッグ位置、長さ、グリッド吸着は操作中に可視化する

### D4. 状態遷移

`NOT_STARTED -> RUNNING(stepId) -> REVIEW -> COMPLETE` を基本とする。

- RUNNING: 何度でも試聴・編集・保存可能。検証成功で次のStepへ
- REVIEW: A/B比較、振り返り、スナップショット保存
- COMPLETE: 課題達成の事実を保持。作品は編集可能であり、過去提出を上書きしない
- 転移課題は別attemptとして作成し、本体の課題とは別に学習履歴を残す
- 任意時点で中断して再開できる。課題Stepと曲面の編集状態はともに復元する

## E. 評価システム

### E1. 分離する3評価

1. **客観条件**: 音符数、音価、開始位置、小節長、コード名、楽器役割数、試聴の実施など。結果はtrue/falseと説明を返す。
2. **分析的な所見**: 同時発音、音域の重複、繰り返し、リズムの分散、コード構成音との関係。良し悪しではなく観測結果として示す。
3. **振り返り**: 自分の制作意図、A/Bで聴いた違い、次に試したいこと。AI採点に一任しない。

### E2. ヒント仕様

- レベル0: ヒントなし
- レベル1: 問いかけ（例「低音を抜くとどう聴こえる？」）
- レベル2: 音楽的原理の説明
- レベル3: 具体的な音符・操作例（差分としてプレビュー）
- レベル3で直接反映する場合は確定前に必ず本人が選択し、Undo可能にする。
- ヒント利用は「苦手さ」ではなく「支援を受けた」という事実として保存する。

### E3. 修了ゲート

- ステップゲート: 当該レッスンの目的に合致する構造化チェックのみ実施
- レッスン達成: 各Step完了 + A/B比較 + 振り返り
- 技能修得の目安: 独立した転移課題で3回中2回成功（初期の仮ルール）
- 芸術的な好き嫌いを修了条件にしない。
- レッスン達成・技能修得・自由制作は別のステータスを持つ。

### E4. 分析ルールのサンプル

- `required_roles_present`: 必要な役割のトラックに有効なノートがある
- `one_root_per_measure`: 本課題の指定小節にコードルートのベース音がある
- `chord_coverage`: 課題指定の各小節にコードを構成するpitch classの組がある
- `drum_pattern_present`: 指定パターンが演奏可能な状態で配置されている
- `comparison_listened`: 同じ区間で比較対象を実際に再生した履歴がある
- `user_variation_exists`: 提出AとBの差分が空ではない
- `phrase_repetition_observed`: モチーフ候補が反復している（所見のみ。単独で減点しない）
- `range_overlap_observed`: 複数役割の音域が重なる（所見のみ。減点しない）

## F. データ設計

### F1. 保存単位

**楽曲Project**: `schemaVersion`, `id`, `name`, `tempoMap`, `meterMap`, `keyHints`, `chordEvents`, `sectionMarkers`, `tracks`, `patterns`, `clips`, `assets`, `snapshotRefs`, `createdAt`, `updatedAt`。

- `track`: id, name, roleId, instrumentPresetId, mute, solo, gain, pan, clipIds
- `pattern`: id, kind=pitched|drum, notes配列（パターン内相対tick）
- `note`: id, pitch(0..127), startTick, durationTicks(>0), velocity(1..127), optional articulation
- `clip`: id, trackId, patternId, startTick, durationTicks, playbackOffsetTick。複製時はリンク共有/独立複製を明示する。
- `chordEvent`: startTick, durationTicks, rootPitchClass, quality, optional bassPitchClass, displayLabel。単純な曲でもコード進行は別レイヤーで保持する。
- `time`: PPQ=480の整数tick。4/4で1小節1,920tick。クオンタイズ、表示、再生秒換算を分離。
- キー表示は参考情報で、キー外の音符を保存時に拒否しない。

**学習Lesson**: lessonId、lessonVersion、requiredSkills、starterProjectRef、stepDefinitions、objectiveRules、hints、reflectionPrompts、masteryPolicy。

**学習Attempt**: id、lessonId、lessonVersion、projectId、currentStepId、completedStepIds、hintEvents、checkResults、listeningEvents、reflectionAnswers、snapshotRefs、status。

**進捗Profile**: skillId、attemptRefs、lastReviewedAt、masteryEvidence、recommendedNextLessons。

### F2. データ整合性

- Projectを復元しても音符のtick、velocity、各楽器の位置が失われない。
- Undo/Redoは音符追加・削除・伸縮、クリップ複製、楽器変更、コード編集に対応。
- スナップショットは不変。あとから現在の編曲を修正しても提出Aが変わらない。
- MIDIのimport/export時にはテンポ、拍子、音符、ドラム割当を明示的に変換・検査する。
- JSONを楽曲の可搬形式、SQLiteを履歴・索引とする。ローカル保存は一時ファイルへの書き込み後の置換と復旧検証を行う。
- 音源ファイルはプロジェクトに必ず埋め込む設計とはしない。ライセンス・配布サイズを確認したうえでプリセット管理をする。

## G. 実装アーキテクチャ

- Tauri 2: ウィンドウ、OS上のファイル・ダイアログ、永続化、配布
- React + TypeScript: UIと状態管理
- Tone.js: 再生イベントのスケジューリング、楽器試聴、トラックミキシング
- Tonal.js: 音階、コード、音程、構成音の純粋計算
- @tonejs/midi: SMFの読み書き。データモデルとMIDIを混同しない
- SQLite: 学習履歴とプロジェクト索引
- すべての音楽編集操作をDomain Commandとして実装し、画面と音声エンジンはその結果を参照する

### G1. モジュール分離

`core/music` : tick、note、chord、pattern、clip、trackの純粋モデル

`core/commands` : 編集操作、検証、Undo/Redo

`audio` : 再生計画生成、音源ローディング、Tone.js adapter

`editor` : ピアノロール、クリップ、ドラムグリッド、コードエディタ

`learning` : Lesson State Machine、課題ルール、フィードバック、ヒント

`storage` : Project JSON、SQLite、Migration、Auto-save

`import-export` : MIDI変換

`test-fixtures` : 教材の基準曲、期待スケジュール、評価結果

### G2. 技術的な注意

- オーディオコンテキストはユーザーのクリック等を契機として開始/再開する。再生失敗時に無音のまま成功表示しない。
- 音符の再生スケジューリングはオーディオ時刻を使い、画面描画・React再レンダリングの速度に依存させない。
- 再生中編集、停止、シーク、ループ切替、全ミュート後復帰で古いイベントや鳴りっぱなしの音が残らないようにする。
- Tone.jsの内部PPQとProjectのPPQは同一と仮定せず、明示的に変換する。
- Tauriのファイルプラグインは実装時点でのRust MSRVとcapability設定を確認する。
- 初期の付属サンプル音は利用・再配布ライセンスが確認できるもののみ採用する。

## H. MVPの実装パスと受け入れ基準

### P0 — Domain + Audio（最優先）

- tick、note、track、pattern、clip、songを純粋モデルとして定義
- 8小節のテスト曲を読み込み、4つのパートを再生できる
- テンポ変更、停止、シーク、ループ再生が機能する
- 重複発音や音の残留などの基本不具合がない
- Gate P0: 同じ入力データでスケジュール結果が再現可能。再生操作テスト合格。

### P1 — エディタ + 保存

- 追加/移動/削除/伸縮、Undo/Redo、クリップコピー、ドラムグリッド
- JSON保存と復元、SQLite上のプロジェクト一覧
- Gate P1: 保存前後の楽曲データ一致、異常終了時の自動保存復元。

### P2 — レッスンの一連の流れ

- S0からS8までの専用教材、課題ルール、振り返り、比較スナップショット
- Gate P2: 初心者向けの操作ガイドで各Stepが完結し、途中再開しても進捗が破綻しない。

### P3 — 基礎学習導線

- U00/U01/U02/U03の代表課題、自由制作モード、用語説明
- Gate P3: 音符編集を知らないユーザーが操作練習から自力で短い旋律を作れる。

### P4 — 学習継続と応用

- U04/U05、編曲・ジャンル横断教材の拡充、MIDI書き出し、技能別の履歴
- Gate P4: 既習素材を使って編曲と独立再挑戦ができる。

> 提案: エンジンの技術検証はP0から、ユーザー向け完成度の確認はU00から。高度なAI講師や多数の音源は後の拡張とする。

## I. 自動テストと手動確認

### 自動テストの最低ライン

1. 4/4、PPQ480の8小節が15,360 ticksになる。
2. quarter=480, eighth=240, sixteenth=120。3連符の8分相当=160 ticks。
3. 楽曲をJSONで保存→再読込してtick/音高/ベロシティ/トラック割当が一致する。
4. 音符の移動→Undo→Redoで開始位置と長さが完全復元する。
5. 共有パターンのリンク複製と独立複製で、片方の編集が正しい範囲にだけ反映される。
6. コードC|Am|F|G|C|Am|F|Cの課題チェックが期待通り動く。
7. 自由制作の非和声音は保存・再生可能で、不必要なエラーにならない。
8. 16ステップグリッドのキック0/8、スネア4/12、ハット偶数ステップが正しいtickに変換される。
9. MIDI書き出しで打楽器ノート36/38/42と該当チャンネル割当が維持される。
10. ミュート/ソロ、ループ切替、再生中停止でイベント残留・音鳴りっぱなしを防ぐ。
11. 8つのStepの進捗を保存して途中再開できる。
12. ヒント利用後の課題完了とヒント未使用の技能達成が混同されない。
13. 比較Aのスナップショットが後続の編集で変更されない。
14. 入力異常（音高範囲外、負の長さ、壊れたプロジェクト）はエラーを安全に返す。
15. 音声エンジン未開始・音源ロード失敗時に、再生済みの判定を行わない。実際に耳へ音が届いたかは自動検知できないため初回にユーザー確認を行う。

### 手動で必ず確認する条件

- 1366×768程度の画面でも編集中心領域が操作できる。
- マウスだけで課題・保存・復元・比較が完結する。
- 画面を見ずに説明を読むだけでも「今何を学んでいるか」が理解できる。
- 課題判定に「このコード・演奏法しか正しくない」と誤認させる文言がない。
- MIDIを書き出して別のDAWで再生し、意図したノートが残っている。

## J. 後続の開発判断

優先順は次のとおり。

1. まずP0のドメインと再生基盤を技術検証する。
2. P1でユーザーが曲を変更して保存できる状態にする。
3. P2のL-U06-01を縦方向に通して、教材エンジンを設計倒れにしない。
4. P3の初級レッスンを補完し、未経験者の入口からつなげる。
5. 複数ジャンルの教材や楽器の種類を追加するのは、上記の使用感を検証してからとする。

**未決事項（着手前の技術検証で選ぶ）**

- 初期音源セットの内容・ライセンス・サイズ
- オーディオレイテンシの実測値と再生中編集の再スケジュール方式
- MIDIインポート対象の範囲とメタデータ保持方針
- 自動保存の具体的な閾値とファイル復旧方式
- デザインテーマ、アプリ名、配布方法

いずれも上のカリキュラムやデータ構造を変えずに決定できるため、設計のブロッカーにはしない。
