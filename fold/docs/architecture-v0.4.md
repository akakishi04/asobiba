# FOLD-LM Core Architecture v0.4

更新日: 2026-09-10。**Gate 1 のLM本体について、保存容量の伸びを抑えながら表現力を増やす設計方針を固定する。現時点では設計仮説であり、性能を実証したものではない。**

v0.3 の FOLD-R + Structural Reasoning は維持する。本書はそれを置き換えるものではなく、これまで独立していた **LMコア側の正規設計と Gate 1 の判定方法** を追加する。LMコアについて本書と過去文書が衝突する場合は本書を優先し、構造推論・応答記憶の詳細は `architecture-v0.3.md` / `architecture-v0.2.md` を参照する。

## 1. Gate 1 の目的

Gate 1 は、巨大な知識量や最大ベンチマーク性能を追う段階ではない。目標は次である。

- 軽量であること。
- 対話用途で高速であること。
- 小型であっても、一般的な言語理解・指示追従・数段階の推論を高い精度で行えること。
- モデルを深くしたり処理の役割を増やしたりしても、保存容量が独立Dense層と同じ割合で増えないこと。
- 後から画像入力を接続できる境界を残すこと。ただし画像認識は Gate 1 の必須条件にしない。

「人間並み」「ユーザー並み」のような主観表現は最終判定には使わない。評価セット、品質指標、速度、保存量、VRAMで判定する。

Gate 1 では次を成功扱いにしない。

- 展開可能な仮想行列の要素数を、保存していないにもかかわらず通常の「パラメータ数」と呼んで大規模化を主張すること。
- 量子化だけでファイルを小さくし、独立重みの増加構造を変えないこと。
- 実行時に各層のDense重みを復元・常駐させ、チェックポイントだけを小さく見せること。
- FOLD-R の検索・外部記憶・深い探索でLMコア自体の品質不足を隠すこと。
- 層数を増やした結果、保存量だけ小さいが生成速度が実用域から外れること。

## 2. 中心仮説: Shared Core + Layer Modulation

通常のDenseモデルでは、層 `i` の各変換に独立した大きな行列 `W_i` を持つ。Gate 1 の第一候補では、大きな行列を少数の共有グループへ集約し、層ごとの差を小さな係数で表現する。

変換の役割 `r`、共有グループ `g(i)` に対して、層 `i` の概念上の重みを次で表す。

$$
W_i^{(r)} = W_{base,g(i)}^{(r)}
+ U_{g(i)}^{(r)}\,\mathrm{diag}(c_i^{(r)})\,V_{g(i)}^{(r)}
+ E_i^{(r)}.
$$

- `W_base`: グループ内で共有する主要重み。
- `U`, `V`: グループ内で共有する調整基底。
- `c_i`: 各層専用の短い係数列。基本的な層差はここに持たせる。
- `E_i`: 共有表現では不足する場合だけ許可する例外重み。初期値は「存在しない / 0」を正規状態とする。

この式は最終形を保証するものではなく、Gate 1 で最初に検証する正規候補である。

### 2.1 完全共有にはしない

モデル全体で一つの `W_base` を使う完全共有を初期正規構成にはしない。入力に近い層、中間、出力に近い層などで必要な役割が異なる可能性があるため、**少数の共有グループ**を持つ。

Attention の Q/K/V/O、FFN の up/gate/down など、役割の異なる線形変換は原則として別の共有系列として扱う。RMSNorm等の小さい層固有パラメータは、共有による節約効果が小さいため独立保持を許容し、総容量へ計上する。

共有グループ数と modulation rank は固定値を仮定せず、アブレーションで決める。

### 2.2 例外重みは「parameter debt」として扱う

`E_i` を無制限に許すと、最終的にDenseモデルへ戻る。そのため例外は次の順で追加する。

1. `c_i` の表現幅を調整する。
2. 必要なら小さな低ランク例外を許可する。
3. Denseな層固有重みは、比較実験で必要性を示した箇所だけに限定する。

例外へ使ったscalar数、bytes、対象層を必ず別集計する。例外量が増え続ける構成は、共有仮説が失敗している可能性として扱う。

## 3. 実行時にDense重みへ展開しない

保存時だけ圧縮して実行時に `W_i` を構築すると、VRAMと帯域の利点を失う。正規forwardは概念上、

$$
y = W_{base}x
+ U\left(c_i \odot (Vx)\right)
+ E_i x
$$

として直接計算する。`W_i` の完全なDense行列を層ごとにmaterializeして常駐させない。

ただし、小さな演算の追加によりkernel launch、memory traffic、同期が増える可能性がある。したがって「保存量が少ない = 高速」とは扱わない。実測tok/sとlatencyで判定する。

量子化、AMP、Flash Attention、speculative decoding等は併用候補だが、この共有構造の効果を確認する実験では独立変数として分離する。

## 4. 容量の増え方

一つの `d x d` 変換を単純化して比較すると、Dense層では概ね

$$
N_{dense} = Ld^2
$$

の独立scalarを持つ。

共有グループ数を `G`、modulation rankを `k` とした候補では概ね

$$
N_{shared} \approx Gd^2 + 2Gdk + Lk + N_{small} + N_{exception}.
$$

ここで `N_small` はNorm等の小さい層固有値、`N_exception` は例外重みである。実モデルでは変換が複数あるため、この式をそのままモデル全体の容量とは呼ばない。

この設計が狙うのは、**深さ `L` に対する保存コストの主項を `Ld^2` から切り離すこと**である。幅 `d` を増やせば共有基底自体は大きくなるため、「どの方向へ拡張しても容量一定」ではない。

また、深さを増やせばforward計算回数は増える。保存容量のスケーリングと推論計算量のスケーリングを混同しない。

## 5. モデルサイズの正規な報告方法

Gate 1 では最低限、次を別々に報告する。

| 指標 | 意味 |
|---|---|
| independent trainable scalars | 実際に独立して保存・学習するscalar数 |
| checkpoint bytes | 配布・保存する実ファイル容量 |
| resident weight bytes | 推論時に常駐する重み容量 |
| peak VRAM | 重み、activation、workspace等を含む実測peak |
| KV/cache bytes | コンテキスト長依存の状態。重みとは分離 |
| active FLOPs/token | tokenあたりに実際に行う計算 |
| tok/s | 定常生成throughput |
| TTFT / token latency | 対話時の体感速度に関わる実測値 |

「仮に各層へ展開した場合の行列要素数」は補助指標として記録してもよいが、通常の独立パラメータ数とは明確に区別する。

## 6. 学習方針

Gate 1 の正規比較では、共有構造を**最初から共同学習**する。大きなDense学習済みモデルを後処理で分解しただけの結果を、正規構成の成功とはしない。

共有重みには複数層から勾配が集まるため、次を監視する。

- 層間で勾配方向が衝突していないか。
- 一部の層だけが共有基底を支配していないか。
- `c_i` が同一化して層の専門化が消えていないか。
- 逆に `c_i` や例外重みだけが肥大し、共有基底が使われなくなっていないか。
- 深くしたときにactivationの数値安定性が崩れないか。

初期実験では、Tokenizer、データ、学習token数、optimizer、評価手順を可能な限りDense baselineと揃える。

## 7. Gate 1 の比較系

少なくとも次を分けて比較する。

| ID | 構成 | 目的 |
|---|---|---|
| A | Dense baseline | 通常の独立層基準 |
| B | Full sharing | 共有しすぎた場合の下限確認 |
| C | Grouped shared base | グループ共有だけの効果 |
| D | Grouped base + layer modulation | 本命構成 |
| E | D + bounded exceptions | 共有で不足する箇所だけ救済 |

量子化やFOLD-R統合をこの比較へ同時投入しない。

比較は一種類の「同条件」だけにしない。少なくとも以下を見る。

1. **同程度の保存容量**で品質がどこまで上がるか。
2. **同程度の品質**で保存容量とVRAMをどこまで下げられるか。
3. **同程度のactive FLOPs / latency**で品質を比較する。
4. 深さを複数点に増やしたとき、checkpoint bytes と品質がどうスケールするか。

## 8. 品質評価

Gate 1 で最低限評価する品質軸は次である。

- held-out next-token loss / perplexity。
- 日本語・英語の基本的な指示理解。
- 数段階の論理・比較・因果・簡単な計画。
- 会話文脈で直前の条件を保持して利用できるか。
- 知らない情報を無根拠に断定する傾向。
- SFT後のtarget-only loss系評価と生成品質。

具体的なベンチマーク集合と非劣性marginは最終比較より前に固定する。テスト結果を見てから合格marginを動かさない。

巨大な百科事典的知識量は Gate 1 の中心目標ではない。ただし知識不足と推論不足を同じ指標に混ぜず、評価時に区別する。

## 9. Gate 1 の合格条件

最終の数値marginは baseline 計測後、最終比較前に文書へ固定する。少なくとも次をすべて満たす候補が必要である。

- Dense baselineに対して、事前定義した品質の非劣性範囲へ入る。
- checkpoint bytes が明確に小さい。
- 層別Dense重みを実行時materializeしない。
- peak VRAM / resident weight bytes の削減が実測できる、または削減できない理由を特定し設計上の利点が存在しない場合は不合格とする。
- tok/s、TTFT、token latency が事前定義した実用範囲を満たす。
- 少なくとも3点の深さ比較で、Denseモデルより保存容量の増加率が小さいことを確認する。
- 例外重みの使用量を全容量へ含め、それを除外しない。

一つも条件を満たす構成がない場合、「実装調整中」として成功扱いにせず、Shared Core + Layer Modulation 仮説を棄却または再設計する。

## 10. FOLD-R / Structural Reasoning との境界

FOLD-Rの応答記憶、Structural Index、仮説探索、推論プログラム再利用は v0.3 の研究対象として維持する。ただし Gate 1 のLMコア比較では原則として無効化する。

順序は次とする。

1. LMコア単体でDense baselineとの比較を成立させる。
2. 共有構造による容量・速度・品質の性質を確定する。
3. その後に FOLD-R / Structural Reasoning を接続し、追加能力と追加コストを別測定する。

外部推論器が強いから小型LMコアも成功、という評価はしない。

## 11. 画像認識の将来接続

Gate 1 ではVision Encoderを実装必須にしない。ただしLMコア入力境界を、将来次の構成へ拡張できるよう固定しすぎない。

```text
Text tokens -------------------------+
                                     v
                                LM Core
                                     ^
Image -> Vision Encoder -> Projector-+
```

Projectorは画像特徴をLMコアが受け取れる埋め込み系列へ変換する。Vision Encoder自体を共有コアへ無理に統合することは Gate 1 では要求しない。

画像生成、動画生成、画像側の長期記憶はこの決定の範囲外である。

## 12. 主な失敗モード

### 表現ボトルネック

共有基底と短い `c_i` では層ごとの差を表せず、品質が落ちる可能性がある。rank / group数 / bounded exception の順で原因を分離する。

### 共有勾配の干渉

異なる深さの要求が同じ `W_base` へ競合する可能性がある。勾配統計と層別性能で確認する。

### runtime overhead

理論上の保存量が減っても、追加の小行列演算・kernel起動で遅くなる可能性がある。実GPUで測定する。

### exception creep

例外を追加するたびに品質が戻るなら、最終的にDenseへ近づく。例外容量をparameter debtとして可視化する。

### 深さと速度の混同

重み共有により深いモデルを小さく保存できても、深いだけ計算は増える。Gate 1 の「高速」は別条件として判定する。

## 13. 実験順序

### G1-A: 測定系を固定

Dense baseline、保存bytes、resident bytes、peak VRAM、FLOPs/token、tok/s、TTFT、品質評価を同一runnerから記録できるようにする。

### G1-B: 共有だけを検証

Full sharingとGrouped shared baseを比較し、「どの程度まで共有すると壊れるか」を先に測る。

### G1-C: Layer Modulation

共有 `U/V` と層別 `c_i` を追加し、group数 × rank の小さなsweepを行う。ここで本命構造のPareto frontierを得る。

### G1-D: bounded exceptions

Cで残る明確なボトルネックだけに例外を許可し、改善量 / 追加byteを測る。

### G1-E: depth scaling

複数の深さでDenseと共有構成を比較し、「層を増やしてもモデルサイズが大きくなりにくい」という中心仮説を直接検証する。

### G1-F: Gate判定

事前固定した非劣性marginと速度条件で合否を決める。Gate 1 合格後にのみ、Vision接続やFOLD-Rとの統合評価を次段へ進める。

## 14. 現時点の決定 / 未決定

### 採用済み

- 第一候補は **Shared Core + Layer Modulation + bounded exceptions**。
- 完全Dense層を深さごとに複製することを正規設計にしない。
- runtimeで層別Dense行列を復元しない。
- モデルサイズは実保存量・独立scalar・VRAMで報告する。
- 量子化は独立の最適化として後から評価する。
- Gate 1 のLMコア性能はFOLD-Rから独立して評価する。
- Visionは後付け可能な入力境界のみ確保し、Gate 1必須にはしない。

### 未決定

- hidden width / head構成 / depth。
- 共有グループ数。
- modulation rank。
- `E_i` を許可する最大容量と形。
- TokenizerとGate 1学習データ。
- 品質の非劣性marginと速度margin。
- Vision Encoder / Projectorの具体方式。

これらは中心仮説を検証できる最小構成から順に固定する。
