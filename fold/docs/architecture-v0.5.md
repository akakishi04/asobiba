# FOLD 最終構想 v0.5 — 共有状態更新コアと圧縮処理部品

更新日: 2026-09-10。

**状態: 最終形に向けた現時点の第一候補。会話で合意した目的と設計仮説を整理したものであり、実装完了・性能実証・学習可能な最大規模を宣言する文書ではない。**

## 1. 範囲と文書の役割

本書は直近ゲートの実装指示ではなく、最終的に何を作るかを定める。個別方式は比較で更新できる。既存モデルとの重み互換性や既存の学習手順に、最終構造を従属させない。

| 本書 | 最終目的、構造の第一候補、学習・評価の方針 |

| [architecture-v0.4.md](architecture-v0.4.md) | 層別共有を切り分けて検証するGate 1の比較候補 |
| [architecture-v0.3.md](architecture-v0.3.md) | 構造推論、予算付き探索、再利用の詳細 |

| [distribution-status.md](distribution-status.md) | コードの所在と、検証済みという主張の区別 |

最終方針では本書と不足情報文書を優先する。v0.4の実験限定の条件を最終形へ拡張しない。一方、v0.2/v0.3の数値保証、scope分離、因果性、費用計上は勝手に緩和しない。

## 2. 目的と採用方針

最終目的は、実用的な言語理解・指示追従・推論を、少ない保存容量と実用的な実時間で成立させること。画像理解を後から接続でき、分からない部分と必要な情報を具体的に示せるようにする。

- 高パラメータ・低容量を狙う。ただし実体のない仮想パラメータ数を大きく見せることを目的にしない。
- 「同品質なら小さい」「同容量なら高品質」を中心に、速度と学習・更新費用も満たす構成を選ぶ。
- 構築・学習・更新が自宅環境で成立することを制約とする。ゼロからの事前学習は必須にしない。
- 既存モデルは比較対象、教材、利用可能な材料として使える。内部構造を維持する義務は持たない。
- 新しさだけでも、実装しやすさだけでも完成形を決めない。既存研究の部品を組み合わせただけで独自の優位性を主張しない。

「ユーザー程度の知能」は動機であって判定指標ではない。対象課題と品質下限は別途具体化する。初期試作の低成績だけで即棄却はしないが、最終的な必要性能を満たさないものは完成形として採用しない。

## 3. 構造の第一候補

**共有する状態更新コア＋圧縮した処理部品群＋計算と情報取得を選ぶ制御器＋訂正可能な記憶**を本命にする。

```text
Text bytes -> Local encoder / causal grouping ----+
                                                  v
Image -> Encoder / Projector -------------> Input representations
                                                  |
                            Recent exact context / working state
                                                  |
                         Shared state-update core <-> Memory reads
                                                  |
                           Controller: answer / compute / acquire
                              | compute                | acquire
                    Selected compressed modules     Bounded runtime
                              |                         |
                         State update <---------- Observed evidence
                              |
                       Repeat within budget or stop
                              |
                    Output representation -> Local decoder -> Text
```

多様性は圧縮部品の種類、処理の深さは再利用、会話で増える情報は更新可能な記憶で担う。これらを同一の「パラメータ増加」として数えない。

### 3.1 共有コアと作業状態

最低限の処理を担当する少数の共有回路は常に通す。作業状態は一つのベクトルではなく、複数のベクトルを持つ小さな領域を候補とする。数、幅、更新規則、初期化方法は未決定。

処理部品は固定された巨大な層列に限定せず、状態に応じて選び、必要なら反復する。部品に「数学」「比較」という意味が自然に備わるとは仮定せず、専門化と選択の両方を学習・検証する。

最近の文脈や作業領域の照合にはAttentionを残してよい。Attention排除そのものを目的にせず、全履歴を毎回処理することを必須にしない。

反復数・使用部品数・作業領域には上限を設ける。状態の変化が小さいこと、複数回答が一致すること、自己申告confidenceの高さを正解の証明にしない。推論時だけ任意に反復を増やしても改善するとは仮定しない。

重みの共有と状態の共有は別である。再帰の段階が違えばKV等の状態も異なり得るため、同じ重みを使う理由だけでcacheを共用しない。入力、段階、scope、revisionとの対応を保つ。

### 3.2 圧縮された処理部品群

部品の保存表現は、概念上次とする。

```text
部品固有の変換
  = 同じ役割・形状の部品で共有する基本変換
  + 共有辞書と短いコードで表すブロック別差分
  + 必要箇所だけの追加補正
```

辞書は小さな重みパターンの集合であり、文章の語彙ではない。各ブロックが複数の辞書から選んだパターンの和を使う方式などを候補とする。全処理部品を同一の低ランク差分だけに制限しない。

共有コア・制御器は比較的高い精度を残し、大きな部品差分は低ビット化する配分を第一候補とする。2〜4bit相当は比較候補であり、確定値・達成値ではない。追加補正の種類、割合、費用を独立に記録し、補正が増えて通常のDenseへ戻る場合も隠さない。

コードで構成可能な要素数は、自由な連続値の数ではない。同じ部品を繰り返し使っても新しい独立パラメータが増えたと数えない。

圧縮重みを保持し、必要な小区画を演算直前に復号して使うことは許容する。禁止したいのは、全層・全部品を高精度Denseへ展開・常駐させ、保存ファイルだけ小さく見せる評価である。復号buffer、kernel起動、転送、paddingも実費へ含める。

### 3.3 制御と実行

制御器は部品の選択・反復・停止に加えて、「追加計算より観測や質問が必要か」を選ぶ。詳細は不足情報文書へ分離する。

部品の入出力shapeは少数の型へそろえ、GPU上でまとめて処理できる実装を候補とする。任意サイズのグラフをCPUから一件ずつ実行する方式を、高速であると無検証で仮定しない。

全パラメータ容量、各更新で動く容量、反復回数は別々に計測する。選択費用や復号費用が省略できた計算を上回るなら、疎な選択が利点を持たない場合もある。

## 4. 入出力・トークナイザー・画像

最終形の第一候補は、UTF-8バイト列を軽い局所処理で受け取り、重いコアには可変長のまとまりを渡す方式である。出力は内部表現から軽いdecoderで文章へ戻す。

固定語彙のBPE/Unigramを比較対象から排除しない。専用語彙、合成的な埋め込み、出力層の圧縮も代替候補に残す。語彙数や方式は最終確定していない。

生成時に未生成の文字を使って区切りを決めない。学習時の対応経路にも同じ因果的な条件を適用する。teacher forcingの未来正解で都合よく区切って生成可能としない。

数字、識別子、引用文には細部の保持が必要なので、最近の原文へ直接アクセスする経路を残す。バイト出力の妥当性、正確なコピー、混在言語、コードも評価する。バイト単位なら自動的に高速とは扱わない。

画像はEncoder/Projectorから位置と入力種別を伴う表現へ接続する。接続口の存在だけを画像理解の実装とは呼ばず、対応付けの学習と実画像による評価が必要である。画像生成・動画生成・デモ動画制作は今回の決定に含めない。

## 5. 記憶との分担

| 領域 | 保存対象と扱い |
|---|---|
| 最近の文脈 | 原文、数字、語順、直前の条件。容量上限を持つ |
| 可変の記憶 | 訂正されそうな関係、整理前の情報、保留中の操作 |
| FOLD-R | 保護する問い合わせ・訂正範囲を定められる関係状態 |
| 必要な原文と出典 | 引用、再確認、圧縮で失う細部。索引を含め有限に管理 |
| 仮説作業領域 | 未確定の候補、追加観測の計画。事実とscopeを分ける |

数値応答の正しさと、自然言語から正しい関係を取り出せたことを分離する。Writer/Reader/Routerは別の学習・評価対象であり、カーネルの保証をそのまま継承しない。

保持範囲外や検索失敗を、事実の不存在へ変換しない。`OUT_OF_SCOPE`、未観測、矛盾、取得不能を区別する。仮説を無検証で事実へcommitしない。訂正や撤回では既存のID・scope・revision規則を維持する。

FOLD-Rの数値精度をニューラル重みの低ビット方針と一括で変更しない。外部記憶の原文・索引・provenance・更新履歴を無料扱いしない。

## 6. 分からないことを扱う能力

回答候補だけでなく、根拠、不明な点、未解決の依存、必要な観測、取得状況を作業状態に持つ。全思考過程の自然言語化は必須にしない。

判断すべきことは、要求の曖昧さ、情報不足、矛盾、推論未完了、不足そのものを特定できない状態の区別である。この区別も推定であり、完全な自己認識を保証しない。

最終的に目指す振る舞いは、**分かる部分を答え、分からない部分を明示し、判断を改善する具体的な情報と取得方法を示すこと**。不要な質問、既に与えられた情報の聞き直し、結論に影響しない空欄埋めを避ける。

モデルは取得を提案し、実行基盤は権限・利用可能なツール・予算を管理する。追加情報を欲しがっただけで外部アクセス権限が増えたり、学習・課金・実機操作が自動承認されたりしない。

詳細な候補状態、行動、学習データ、評価は [information-acquisition.md](information-acquisition.md) を参照する。

## 7. 学習と構築の自由度

ゼロからの学習、既存モデルの変換、出力からの蒸留、部分学習、圧縮後の再調整を利用候補にする。完成形の構造と、その作り方を分ける。既存モデルとの内部互換性を採用条件にはしない。

- 教師が生成した文章等を先に保存し、教師と学習モデルを同時にGPUへ置かない構成を許す。
- 入出力単位が違う場合、教師のtoken IDやlogitをそのまま対応させない。まず文章として教材化し、内部対応が必要な方法は別検証とする。
- 共有コア、部品、制御器、記憶の読み書きを、必要に応じて段階的に更新する。
- 低ビットのコード番号は通常の連続値と同じようには微分できない。辞書の調整、割り当て変更、近似勾配等を明示し、保存形式と学習時表現を分ける。
- 高精度コピー、optimizer state、activationの全量常駐を必須にしない。再計算、部分更新、CPU/RAM/ストレージ利用は総実時間を含めて比較する。
- 教師の能力を利用した場合、その由来と生成費用を記録する。独力でゼロから能力を獲得したとは報告しない。

自宅環境のGPU容量、RAM、保存領域、許容時間は実験manifestで確認する。会話中の16GB級単一GPUは暫定の検討前提であり、この構成の実機検証結果ではない。収まることだけでなく、繰り返し改善できる構築・更新時間かを見る。何十億要素まで育てられるかは未確定。

モデル・教材の利用条件と出典は取得前に確認する。本書は大規模ダウンロード、課金API呼び出し、学習ジョブ開始を承認しない。

## 8. 容量と性能の報告

少なくとも以下を区別する。

| 指標 | 計上対象 |
|---|---|
| 独立した連続学習値 | 辞書、共有重み、調整値、補正など |
| 離散コード数と実ビット数 | 部品ごとの割り当て。連続学習値とは分離 |
| 構成可能な重み要素数 | 符号化対象の補助指標。同じ部品の反復分を加算しない |
| 配布時の実保存量 | 重み、全辞書、コード、scale、補正、設定、必要な入出力資産 |
| 推論時メモリ | 常駐重み、復号buffer、KV/状態、workspace、peak RAM/VRAM |
| 記憶の総費用 | 原文、索引、capsule、provenance、検索・訂正時間 |
| 構築・学習費用 | 教師生成、変換、再学習、高精度コピー、学習状態、peak RAM/VRAM、実時間 |
| 推論費用 | 動く部品、反復、実演算量、TTFT、同じ文章/課題の完了時間、遅延分布 |

「平均bit/要素」を出す場合は、どの要素を分母にし、辞書等を分子へ含めたかを明記する。数字だけで能力を換算しない。少数の保存情報から任意の独立重みを無制限に復元できるとは主張しない。

異なるTokenizer間のtokens/sやper-token lossをそのまま優劣に使わない。同じ元文章・情報量、課題品質、総実時間で比較する。必要なら同じ評価テキストのbyte当たりNLL等を併記し、符号化条件も記録する。

## 9. 評価方針

これは最終構想の検証軸であり、直近ゲートへ全機能を一括実装する指示ではない。

1. **構造の効果:** 独立部品、共有のみ、符号化のみ、共有＋符号化を比較する。固定反復と動的反復、固定入出力と可変長入力も切り分ける。
2. **実用性:** 同容量の既存量子化モデル、単純な共有/再帰モデル、独立した条件付き部品モデルを対照にする。利用可能な実装と実機条件をその都度確認する。
3. **能力:** 日本語・英語、指示理解、推論、文脈利用、正確な文字列、知識不足と推論不足、未学習分布を分ける。
4. **情報取得:** 誤断定だけでなく回答率、不要質問率、取得後の改善、往復数、ユーザー負担、時間を測る。
5. **記憶と画像:** コア単体、記憶あり、情報取得あり、画像ありを分離報告し、完成システムの総費用も測る。

構造を切り分ける比較では、入力表現、教材、学習量、計算予算を可能な範囲でそろえる。構築手段の実用比較は別枠にし、教師利用や事前学習量の差を明記する。評価データと教師生成物の漏洩・重複を確認する。

品質下限、容量・速度の目標、非劣性margin、計算/情報取得予算は最終比較前に固定する。ゲートの小さな数値課題通過を、一般言語能力・自己認識・画像理解の証明にはしない。

既存モデルを単純に量子化した方が、同じ総容量で必要品質と速度を満たすなら、その時点の独自候補を完成形に採用しない。失敗原因を共有、符号化、制御、学習、入出力、記憶に分けて再設計する。

## 10. 未決定事項と主なリスク

未決定は、状態更新式、作業slot数/幅、部品数/shape、共有範囲、辞書の粒度、コード数/ビット幅、補正予算、ルーティング学習、停止学習、入出力の区切り方、Vision方式、教材と学習予算、各評価閾値である。

共有勾配の干渉、部品選択の偏り、使われない部品、圧縮誤差、補正の肥大、復号・切替コスト、反復時の状態増加、Writer誤り、過剰な質問、自信のある誤答を主要な失敗モードとして記録する。

本命構造を全て一度に載せること自体は成果ではない。中心仮説は、**部品の共通部分を共有し、違いを短いコードで保持し、使い方を学習することで、保存容量に対する実際の能力を改善できるか**である。
