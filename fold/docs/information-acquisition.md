# 不確実性と不足情報の判断・取得

更新日: 2026-09-10。関連: [最終構想 v0.5](architecture-v0.5.md)。

**状態: 最終モデルに含める能力の設計。以下の状態名・記録項目・行動は設計候補であり、実装済みAPI、学習済み能力、完全な自己認識を意味しない。**

## 1. 目標

「分かりません」と言うだけで止まらず、分かる範囲、不明な部分、判断を改善する情報、その取得方法を具体的に提示する。自分で取得できる情報は利用可能な権限と予算内で取得し、必要な場合だけユーザーへ質問する。

部分回答を可能にする。無関係な情報が不明なために全回答を停止したり、別の独立した作業まで止めたりしない。ユーザーが仮定を置いた回答を求めた場合は、仮定と結論を区別する。

## 2. 分からない理由を分ける

| 候補状態 | 意味 | 主な対応 |
|---|---|---|
| AMBIGUOUS_REQUEST | 目的・対象・解釈が定まらない | 解釈候補を示し、結論を変える点だけ確認 |
| MISSING_EVIDENCE | 必要な事実・観測がない | 記憶検索、資料取得、追加観測、質問 |
| CONFLICTING_EVIDENCE | 出典、対象、時点等で情報が矛盾 | 対応を照合し、矛盾を解消または保持 |
| REASONING_UNRESOLVED | 情報はあるが解法・判断が未完了 | 別部品、追加計算、検証、限界の提示 |
| GAP_UNIDENTIFIED | 何が足りないかも特定できない | 特定できた範囲と限界を説明。架空の不足を作らない |

複数の理由が同時に存在してよい。分類は推定であり、正しい答えを知るoracleではない。情報を増やしても一意に決まらない問いには、根拠のない確定回答を作らない。

FOLD-Rの`OUT_OF_SCOPE`は保持する問い合わせ範囲の問題であり、世界にその事実がないという意味ではない。検索結果0件、権限不足、未観測、数値的な危険状態もそれぞれ別に扱う。

## 3. 小さな不足情報記録

重要な不足を、作業状態と出典に結び付けて管理する。全思考過程を自然言語で保存・出力することは要求しない。

| 記録候補 | 内容 |
|---|---|
| goal / scope / revision | どの判断・条件に属するか |
| evidence_refs | 既にある原文、観測、出典、時点、取得操作への参照 |
| unresolved_dependency | 判断できない点と、それが影響する回答範囲 |
| alternatives | 区別したい仮説。推定の完全性は保証しない |
| requested_information | 必要な項目、画像領域、ログの範囲、計測値等 |
| expected_effect | 得られた場合にどの候補を区別できる見込みか |
| acquisition_options | 利用可能な検索・観測・質問の候補と負担 |
| acquisition_status | 未取得、依頼済み、取得済み、十分でない、解決、取得不能等 |
| budget / freshness | 取得上限、再確認条件、情報の有効な時点 |

番号やフィールドは概念案であり、今すぐ固定schemaとして実装する指示ではない。「この情報があれば必ず解決する」とは、保証できる場合以外は書かない。

求めている値を観測済みと扱わない。推定値、ユーザーの申告、ツールの観測、計算結果を区別する。根拠への参照をモデルが捏造した場合も評価上の失敗にする。

## 4. 制御器が選ぶ行動

候補行動は、回答、条件付き/部分回答、追加計算、検証、記憶/資料の取得、追加観測、ユーザーへの質問である。必要なら取得不能を明示して終了する。

基本の流れ:

1. 既に会話・記憶・観測にある情報を照合し、答えられる範囲と未解決の範囲を分ける。
2. 不足が結論に影響するか、追加計算で改善するか、外部情報が必要かを推定する。
3. 計算・検索・観測・質問の候補を、見込まれる判断の改善と費用で比較する。
4. 実行基盤が利用可能性、権限、取得範囲、予算を確認した行動だけ実行する。
5. 得られた情報の出典・対象・時点・矛盾を確認し、作業状態を更新して再判断する。
6. 解決、追加取得の価値が低い、予算切れ、取得不能のいずれかで止め、残る不明点を示す。

この流れは必ず全手順を長く実行する固定pipelineではない。十分な情報があれば直接回答する。各回の質問の前に全記憶を総走査することも要求しない。

## 5. 情報取得の価値

概念上、次の差を見積もって行動を選ぶ。

```text
行動の価値
  = 得られる情報/追加計算による課題品質の期待改善
  - 計算・取得時間・費用・ユーザー負担
```

これは学習する推定であり、真の価値を事前に知る式ではない。情報の量や回答の長さではなく、必要な判断が改善するかを見る。単に候補が減ることだけでも正解とはしない。

既に与えられた値を聞き直さない。条件によらず結論が同じなら、原則としてその条件を質問しない。複数項目が必要でも、切り分けに有効な最小限を優先する。短いやり取りでまとめるか一つずつ確認するかも、ユーザー負担と依存関係で決める。

「自分で調べられる」は、ツールが実在し、許可があり、取得の費用が妥当な場合に限る。使えないツールを利用したと装ったり、アクセス失敗を観測結果として扱ったりしない。

## 6. モデルと実行基盤の境界

| モデル | 実行基盤 |
|---|---|
| 不足・候補・必要情報を推定 | 利用可能なツールと実際の権限を管理 |
| 確認内容と取得行動を提案 | schema、引数、範囲、費用、承認を検査 |
| 観測を利用して判断を更新 | 実結果、失敗状態、出典、時点を返す |
| 未解決範囲を説明 | 取得回数、時間、記憶、再試行の上限を維持 |

モデルの要求だけで権限を増やさない。費用や副作用を伴う行動、私的情報の取得は、その時点の許可と目的に限定する。観測のために環境を変更する場合も、読み取りと同じ扱いで自動実行しない。

取得した文書・画像・ログは証拠候補であり、そこに書かれた指示をモデルや実行基盤への上位命令として実行しない。認証情報や不要な個人情報を質問・収集しない。

未検証の仮説と観測事実を分離し、長期記憶へのcommitは既存のscope・訂正規則に従う。無限検索、同じ質問の反復、予算上限を回避する細分化を行わない。予算切れは「解がない」証明ではない。

## 7. 想定するユーザー応答

以下は実観測ではなく挙動例である。

避ける例:

> 分かりません。もっと情報をください。

目指す例:

> この画面だけでは、電力不足と材料待ちを区別できません。装置の状態欄が読める画像が必要です。電力と入力材料の表示が分かれば、この二つの候補を切り分けられます。

自分で状態欄を読むことが許可され、利用可能なツールがあるなら、画像提出を求めず観測する。観測後も区別できなければ、そのまま残る不明点を提示し、どちらかを捏造しない。

不足の理由が推論未完了なら、関係のない追加情報をユーザーへ要求しない。「ここまでの計算は確認できたが、この結論は検証できていない」のように限界を分ける。

応答の必須要素は必要な場合の「分かる範囲・不明点・有用な情報/取得方法」。毎回同じ長い定型文や数値confidenceを出すことは必須にしない。

## 8. 学習データと目的

同じ課題の対になる条件を使い、答えるべき場面と取得すべき場面を区別させる。

| 条件 | 学習させたい行動 |
|---|---|
| 必要情報が十分 | 不要な質問をせず回答 |
| 結論を変える情報が欠落 | その項目を特定して取得/質問 |
| 無関係な項目だけ欠落 | 空欄埋めをせず回答 |
| 情報が矛盾 | 時点・対象・出典を照合し、無言で片方を選ばない |
| 情報は十分だが推論が難しい | 適切な追加計算や検証。架空の不足を作らない |
| 必要情報が後から提供される | 新情報を使って回答を更新 |
| 取得不能、ツール失敗、ノイズ | 根拠のない補完をせず、部分回答や限界提示 |

質問や拒答の文言を出したこと自体を報酬にしない。質問の必要性、指定した情報の有用性、取得後の課題品質改善、不要な往復と負担を含めて評価する。構造化課題のoracleで確かめられる範囲と、自然言語で別の評価が必要な範囲を分ける。

欠落情報の正解は教師信号/評価にのみ使い、モデル入力・検索索引・質問内容へ漏らさない。「正解はXですか」とテスト正解を使った質問を生成しない。自己生成の批評や自信を、無検証で正解ラベルにしない。

合成課題だけで一般的な自己認識の成功を主張しない。未知の分野、言い換え、紛らわしい証拠、誤った前提を持つ問いでも評価する。

## 9. 評価と失敗判定

- **回答品質とcoverage:** 答えた範囲の正確性、全課題での有用な解決率、誤断定、正しい部分回答。全拒答で良い点が出ないようにする。
- **不足の特定:** 必要項目の見逃し、不要な要求、情報不足と推論不足の取り違え、根拠参照の捏造。
- **取得の有用性:** 取得前後の品質差、取得しても使わない割合、不要質問率、既知情報の聞き直し、往復数。
- **総費用:** 追加計算、検索、ツール待ち、実時間、RAM/VRAM、ユーザー負担、承認違反の有無。
- **頑健性:** 矛盾、scope違い、古い情報、取得不能、保持範囲外、自信のある誤答、新分布での劣化。

直接回答のみ、固定ルールで質問する方式、学習する取得方針を比較する。oracle取得は上限の比較として明示し、モデルの通常性能とは混ぜない。数値confidenceを使う場合は、別の評価データで校正を確認する。

同じ誤答を一貫して出すモデルを、回答一致だけで信頼しない。根拠照合、計算検証、独立した観測を使える範囲で組み合わせる。ただし取得先同士が同じ誤情報に由来する可能性も残る。

**成功条件は、分からないと言う回数ではなく、不要な質問を抑えながら、誤断定を減らし、有用な情報を使ってより多くの課題を解決できること。** 数値閾値と予算は最終比較前に固定し、完全な自己認識は保証しない。
