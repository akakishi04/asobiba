# Comfy Orchestrator（asobiba / main）

用意済みの **ComfyUIワークフロー**を自然文から実行する、Windows向けローカルGUIです。LLMの解釈には **LM Studio** を標準採用し、追加のOllama導入は不要です。Python 3.11+ と標準ライブラリだけで動きます（Tkinterは通常のWindows版Pythonに同梱）。

## まずGUIを起動する

1. **LM Studio 0.4.0以降**を起動し、**Developer / Local Server** からサーバーを有効にする（標準ポート `1234`）。
2. ComfyUIを通常どおり起動する（標準ポート `8188`）。`waiIllustriousSDXL_v170.safetensors` がComfyUIに配置済みであること。
3. Windowsで `comfy-orchestrator/run_gui.bat` をダブルクリック。あるいはPowerShellから:

   ```powershell
   cd M:\asobiba\comfy-orchestrator
   python -m comfy_orchestrator.gui
   ```

4. GUIの **「モデルを更新」** からLM Studioにインストール済みのモデルを選ぶ。
5. **「接続確認」→「設定を保存」** で接続と設定を確認する。
6. 自然文を入力して **「解釈のみテスト」** でLLMの変換結果を確認。
7. 問題なければ **「画像生成を開始」** でComfyUIに投げる。

ウィンドウの右側に生成結果をプレビューし、画像は `comfy-orchestrator/outputs/` へ保存します（Git管理外）。日本語入力に対応しています。

### 画面で調整できる項目

- LM Studio / ComfyUI のURL、LLMモデル選択、接続確認と設定保存
- 固定ワークフローの選択（自動選択または明示選択）
- 自然文、参照画像（**I2I/I2Vの登録後に有効**）、幅・高さ・Steps・CFG・Seed
- LLM解釈だけのテスト、ComfyUI生成、実行ログ、出力画像の一覧とプレビュー
- **「待機を中止」** はクライアント側の待機だけを停止し、ComfyUIに投入済みの生成ジョブは停止しません。

画面の軽量初期値は **768×768 / 20 Steps / CFG 5.0** です。ユーザーがエクスポートした固定ワークフロー原本は **1024×1024 / 28 Steps / CFG 5.5** のまま保持しています。精細さが必要ならGUIで設定を変更してください。

**Seedの扱い:** GUIのSeedが空欄なら、毎回アプリ側で安全な32bit乱数を生成します。Seedを明示入力した場合は、その値を優先して再現性を保ちます。LLMにはSeedの選択を任せず、不正なSeedを返しても採用しないため、LLM由来のSeed範囲エラーで画像生成が停止しません。


## 日本語入力・画面の見やすさ

GUIの入力欄を**コンパクトな6行のエディタ**に変更し、`Meiryo UI`・広めの行間・余白を採用しています。長い文章は欄内スクロールで入力できます。画面右上の **「ダーク表示」** で明暗を切替可能です。入力欄右上の `A−` / `A+` ボタンで**文字サイズを10～20pt**の範囲で調整できます。既存の入力文を消さずに切り替えられます。

色設定と文字サイズは「設定を保存」で `config.json` に保存され、次回起動時に復元します（Git管理対象外）。画像生成、ワークフロー、LLM解釈には影響しません。

**日本語IME変換中文字のフォント補正:** Tkinterでは、文字の確定前だけWindows IME側の別フォントで大きく表示されることがあります。Windows環境では入力欄にフォーカスしたときとIMEキー入力時に `ImmSetCompositionFontW`（Win32標準API）を使用し、入力欄と同じフォント名・サイズをIMEへ通知します。フォントサイズ変更にも追従します。IMEやWindows側の実装差で反映されない場合があるため、最終的な効果はWindows実機で確認してください。

**別問題：IMEの予測候補ウィンドウ**（「Tabキーを押して選択します」の一覧）はWindows側のUIで、上記の補正対象ではありません。必要な場合のみMicrosoft IMEの「予測入力」で別途設定してください。

## 起動時レイアウト・小さめの画面への対応

入力やポーズ参照の機能が増えても、**画面下部のボタンが見切れない**ようにレイアウトを変更しました。

- 初期ウィンドウサイズと最小サイズは、Windowsが通知する画面の幅・高さに合わせて決定します。従来の固定 `1240×910`／最小 `960×760` は使いません。
- 左側の**自然文・生成設定は独立した縦スクロール領域**です。マウスホイールか右端のスクロールバーで参照画像、部分修正、ポーズ参照まで移動できます。日本語の自然文エディタ内でのスクロールは従来どおりエディタが担当します。
- **「解釈のみテスト」「画像生成を開始」「待機を中止」**は入力欄の下に固定し、スクロール位置に依存しません。
- 右側の結果・履歴タブも、画像を開く／再生成／比較などの操作ボタンを下部に固定しました。
- **実行ログは初期状態で非表示**です。画面下の「ログを表示」ボタンで展開できます。ログを閉じても内容は保持し、新しい記録も追加されます。
- プレビュー画像は利用可能な領域に合わせて縮小表示します。画像の保存データ自体は縮小しません。

特にノートPCやWindowsの表示スケール125～150%で画面の有効高さが少ない環境を想定しています。マルチモニター環境や独自のタスクバー配置では、実際の表示領域に差があるため、必要ならウィンドウサイズを手動調整してください。

## LM Studioのトークン設定

標準値を **コンテキスト長8,192 tokens / 最大生成4,096 tokens** に設定しています。出力のばらつきは従来どおり `temperature=0.2` です。

- `config.example.json` の `llm.context_length=8192`：LM Studioのモデルを新規ロードするときのコンテキスト上限。
- `llm.max_tokens=4096`：`/v1/chat/completions` に渡す最大生成トークン数。**常に4,096トークン生成するわけではなく上限**です。
- 既存GUI設定が旧標準値の4,096コンテキスト・2,048出力だった場合は、次回のGUI起動時に新しい標準値へ一度だけ移行します。その後GUIで「設定を保存」または生成を実行すると、変更がGit管理外の `config.json` に保存されます。既に標準値以外を指定したユーザー設定は保護します。
- LM Studio側で既にモデルがロードされている場合は、そのモデルインスタンスのコンテキスト設定が優先されます。新しい8,192トークン枠を確実に使いたい場合は、LM Studio側で既存インスタンスをアンロードしてからGUIで解釈を実行してください。
- 推論用トークンの上限を増やすため、場合によってはLLMの計算時間やVRAM使用量が増えます。必要なら `config.json` で値を調整できます。

## LM Studioでタイムアウトする場合

Thinkingを使用するローカルLLMは、4,096 tokensの生成上限を活用すると解釈に4分以上かかることがあります。以前の `llm.timeout_seconds=240` は全APIで共通だったため、実際の応答が完成する前に通信が切れる場合がありました。

- `llm.inference_timeout_seconds=600`：LM Studioの **`/v1/chat/completions` だけ**に適用する通信待機上限（10分）
- `llm.timeout_seconds=240`：モデル一覧、ロード、アンロードなど従来のAPI操作用（4分）
- `comfyui.generation_timeout_seconds=1800`：画像生成の完了を待つ時間（従来どおり30分）

GUI起動時、既存のローカル `config.json` に新項目がなければ600秒を補完します。GUIの「設定を保存」で反映されます。手動で増減する場合はローカル `config.json` の `llm.inference_timeout_seconds` を編集してください（30～3,600秒）。

タイムアウト時は、どのLM Studio API操作で発生したか表示します。**延長しても確実に成功する保証はありません。** メモリ不足、モデルの応答停止、極端に低いtoken/s等でも応答が遅くなるため、再発する場合はLM Studioのログと実測速度を確認してください。自動リトライは行わず、重複実行を避けます。

## 生成履歴・画像比較・再生成

GUI右側に **「今回の結果」** と **「生成履歴」** のタブがあります。

- **履歴:** 生成成功時に元の日本語指示、LLMが決めたPositive/Negativeプロンプト、ワークフロー名、Seed、Steps、CFG、Denoise等をローカルSQLiteに保存。画像ファイルは従来どおり `outputs/` 内に保持します。
- **I2I元画像の保存:** 元画像を `data/references/` にコピーして参照するため、後から元ファイルを移動しても比較・再生成が可能です。
- **設定を復元:** 履歴を1件選んでボタンを押すと、自然文・ワークフロー・生成設定・参照画像を編集画面へ戻します。そこから文面を変えて新たに生成できます。
- **同じSeedで再生成:** 以前のPositive/Negativeと数値設定をそのまま再利用し、LLMを呼び出さずComfyUIで再実行します。画像のピクセル完全一致を保証するものではありません。
- **別Seedで再生成:** プロンプトなどは維持したままSeedのみ乱数に変更します。
- **画像比較:** I2I履歴を1件選ぶと「元画像 / 生成結果」、T2I履歴をCtrl+クリックで2件選ぶと「生成結果A / B」を並べて比較できます。比較ウィンドウには連動した倍率変更とスクロールがあります。
- **過去の出力:** この機能の追加前に `outputs/` にあった画像は、既知のファイルのみ「旧画像（設定不明）」として取り込みます。古い設定は復元できないため、履歴からの再生成ボタンは使用できません。

保存先は `comfy-orchestrator/data/history.sqlite3`、I2I参照元のバックアップは `data/references/`、出力画像は `outputs/`。どれもGit管理外です。履歴の削除機能はまだありません。アプリは個人利用のローカル履歴として扱い、クラウドへの同期は行いません。

**表示形式:** 標準のTkinterでPNGを比較できます。JPEG/WebPの元画像を比較する場合や滑らかな任意倍率の拡大縮小には、任意で `python -m pip install Pillow` を実行してください。PillowはGUI起動や画像生成には必須ではありません。

## 画像からI2I・部分修正・ポーズ参照（追加機能）

### 自動切替

- **参照画像が空、ポーズ画像も空** → 自動的に `wai_t2i_basic`（T2I）を選択します。直前がI2Iや部分修正でもT2Iへ戻ります。
- **参照画像を選択** → `wai_i2i_basic`（通常I2I）へ切替。
- **参照画像を選択し「範囲を塗る...」でマスクを確定** → `wai_inpaint_basic`（部分修正）へ切替。マスクを消すと通常I2Iに戻ります。
- **ポーズ参照を選択** → `wai_pose_skeleton` または `wai_pose_detect`（ポーズのみを使ったT2I）へ切替。通常I2Iの元画像とは排他です。ポーズ参照を消すと通常T2Iへ戻ります。

「今回の結果」の「この画像からI2I」、または履歴で1件選択して「選択した画像をI2Iの元画像にする」を押すと、生成済み画像を直接次のI2I入力にできます。

### 部分修正（Inpainting）

1. 元画像、または生成結果からI2I入力を選びます。
2. **「範囲を塗る...」** を開き、修正したい領域だけを赤色のブラシで塗ります。Undo・全消去が可能です。
3. **「この範囲を使う」** で元解像度の白黒マスクをローカル保存します。**白＝描き直す／黒＝元画像を維持する**。
4. 自然文に「手の指を自然に修正する」などと入力し、通常どおり生成を実行します。

ワークフローはComfyUI標準の `LoadImageMask`、`VAEEncodeForInpaint`、`ImageCompositeMasked` を利用。**未指定領域のピクセルを元画像から戻す構造**ですが、マスク境界は不自然になる可能性があります。必要ならマスクを少し広げて調整してください。一般SDXLチェックポイントを使う簡易Inpaintingであり、専用Inpaintモデル相当の保証はありません。

**必要な追加Pythonパッケージ**：GUIのマスク描画のみ `Pillow` が必要です。通常のT2I/I2Iには不要。GUIを起動するPythonに次を実行：

```powershell
python -m pip install Pillow
```

### 構図参考画像だけからT2I（ControlNet不要）

**「構図参考（LLMのみ）」** は、通常の「参照画像（I2I）」や「ポーズ参照（ControlNet）」と独立した欄です。DesignDollの通常のスクリーンショットや既存イラストを指定すると、**画像対応LM Studioモデルがカメラ視点・人物配置・ポーズ・トリミング等を文章で読み取り、T2IのPositiveプロンプトに反映**します。構図参考の画像自体はComfyUIには送信しません。

1. LM Studioのモデル一覧から画像対応VLMを選択します。
2. **「構図参考（LLMのみ）」→「参照...」**でPNG/JPEG/WebPの画像を選択。GUIの「画像をLLMで構図解析し、プロンプトに反映」が自動でONになります。
3. 通常の「参照画像」と「ポーズ参照」は空欄にしておくと、**自動で通常T2I**が選択されます。
4. 日本語で「この画像の構図と視点を使い、キャラクターは白い服の少女にして」などと入力。まず「解釈のみテスト」で構図のタグを確認し、生成します。

通常I2Iと併用する場合は、通常の「参照画像」に元絵を、こちらに構図画像を別々に設定できます。ただし、最終的な位置関係は**文章指定のみでは厳密には固定されません**。マネキンのポーズの忠実な再現には、従来のOpenPose ControlNetのほうが強い制御です。

この画像はローカルのLM Studioにのみ送信され、生成履歴にはコピーを保持します。過去の履歴も非破壊でデータベース移行します。構図指定はPositiveプロンプトに含まれるため、同じSeedでの再生成は画像解析やLLMロードなしで実行できます。

### 画像対応LLMで構図を解析してプロンプトに反映

画像を読み込んで生成する場合、左の設定欄にある **「画像をLLMで構図解析し、プロンプトに反映」** をONにできます。ローカルのLM Studioから**画像入力に対応したVLM**を選択してください。通常の文章専用LLMは画像を解析できません。

- **I2I／部分修正**：元画像をLLMへ渡し、カメラアングル、画面内の人物の位置、構図、視線、身体の向き、トリミング、奥行きなどを解析。ユーザーが入力した変更指示を尊重し、具体的な英語タグをPositiveプロンプトへ追加します。
- **ポーズ参照**：DesignDoll等の通常画像、またはOpenPose骨格PNGをLLMにも渡します。**参照するのは視点・ポーズ・人物配置のみ**と指示し、マネキンの材質、服の色や背景は生成にコピーしません。生成時の画像は別途ControlNetへ送られます。
- **画像指定なしのT2I**：「構図参考」も空欄なら画像はLLMに送信せず、従来の文章入力のみで生成します。
- **モデルの確認**：LM Studioのモデル一覧で`capabilities.vision=false`が明示されたモデルは、画像を渡す前に拒否します。未報告のモデルは推論時に対応可否が判定されます。
- **OFFの場合**：従来どおり画像をComfyUIだけに送信し、LLMは日本語指示を文章から解釈します。

例：「この人形の**構図・カメラ視点・ポーズのみ**を参考に、白いワンピースの少女を描いて。背景は海辺。」と入力します。実際にLLMが生成した構図指定は「解釈のみテスト」のログから確認できます。

**制限：** LLＭが生成するのは**文章による構図指定**であり、画像内の関節位置や座標を正確に固定するものではありません。精密なポーズ・構図保持にはOpenPose ControlNetと併用してください。画像の解析はテキストのみの場合より時間とメモリを使うため、生成前にLLMをアンロードする既存の処理を維持します。画像は設定したローカルLM Studioサーバーへ送信されます。

### DesignDoll / 人物画像のポーズのみ参照

**2種類の入力モード**があります。

- **骨格PNGを直接利用**：OpenPose形式（黒地に色分けされた骨格線）の画像を指定。すでに骨格化されているため、外観・服の色などは読み込まず、ポーズ制御に使います。`wai_pose_skeleton`。
- **通常画像から骨格検出（DWPose）**：DesignDollの人形スクリーンショットや人物画像を指定。DWPoseで関節位置を抽出してからControlNetへ渡します。`wai_pose_detect`。被写体や関節の隠れ方によって誤検出する場合があります。

どちらのモードも **追加モデルの導入が必要** です：

1. SDXL OpenPose ControlNet [xinsir/controlnet-openpose-sdxl-1.0](https://huggingface.co/xinsir/controlnet-openpose-sdxl-1.0) から `diffusion_pytorch_model.safetensors` を取得。必要なら `controlnet-openpose-sdxl-1.0.safetensors` とリネームして、`ComfyUI/models/controlnet/` へ配置します。**ワークフローはこのリネーム後のファイル名を参照**します。ComfyUIを再起動してください。
2. 通常画像から骨格を推定する場合は、ComfyUI-Managerで [comfyui_controlnet_aux](https://github.com/comfyorg/comfyui-controlnet-aux) をインストール。DWPose関連の検出モデルも使用します。
3. GUIの「ポーズ強度」で制御の強さを調整（初期0.85）。幅・高さは通常のT2I同様に変更できます。

参照用のSDXL ControlNetは約2.5GBの追加モデルです。16GB VRAMでは通常のI2Iより計算・メモリ負荷が増すため、最初は768×768・20steps程度で動作確認してください。**モデルはこのアプリから自動ダウンロードしません。** 不足しているモデルやDWPoseノードは生成前にエラー表示します。Illustrious SDXLとの互換性・ポーズの再現度は実機検証が必要です。

### 履歴との連携

部分修正時の**元画像とマスク**、ポーズ参照時の**入力ポーズ画像**は、生成履歴にそれぞれ保存されます。以前の履歴DBも自動移行し、画像を変えずに再生成できます。複数案生成は今回追加していません。

## 実行時のモデル解放とPC負荷

```text
日本語入力
  ↓
LM Studioの指定LLMをロード（すでにロード済みなら再利用）
  ↓
LLMが固定ワークフローと許可された入力をJSONで決定
  ↓
LM Studio APIで、そのLLMインスタンスのアンロード完了を確認
  ↓
ComfyUIへ固定ワークフローをキュー投入
  ↓
ComfyUIで画像生成 → 出力取得・表示
```

GPUメモリ節約のため、GUI初期状態で「LM Studioモデルを解釈後にアンロード」がONです。**選択したモデルがLM Studioの画面で事前ロードされていても解放します。** 別のLLMを巻き込んでアンロードしません。ComfyUI側の前回モデルの解放は、キューが空の場合に限って要求します。

実際のVRAM解放量は各プロセス・GPUドライバーに依存します。ComfyUIの `/free` は非同期要求であり、完全解放の保証ではありません。必要なモデルファイルのロード時間は発生します。

## 既存の固定ワークフロー

| ID | 種類 | API JSON |
|---|---|---|
| `wai_t2i_basic` | T2I / アニメイラスト | `workflows/wai_t2i_basic.api.json` |
| `wai_i2i_basic` | I2I / 参照画像から描き直し | `workflows/wai_i2i_basic.api.json` |

`config.example.json` には、ノードIDと入力の対応を登録済みです。I2Iは元画像を`LoadImage (16)`で読み込み、`VAEEncode (17)`を通して`KSampler (11)`へ送る構成です。元の出力設定のDenoiseは `0.53` です。

### I2Iの使い方（Windows GUI）

1. **参照画像** からPNG/JPEG/WebPを選択します。画像が選ばれるとワークフローが `wai_i2i_basic` に自動切替されます。
2. 日本語で「服の色を青に」「表情を笑顔に」など変更内容を入力します。
3. **Denoise (I2I)** を調整します。目安は `0.3`（原形を強く維持）～ `0.7`（大きく描き直し）で、初期値は `0.53` です。
4. 「解釈のみテスト」で指示の変換を確認し、「画像生成を開始」でComfyUIに送ります。

- **I2Iの出力解像度は参照画像と同じ**です。元画像が224×224なら生成も224×224です。GUIの幅・高さはI2Iで無効化します。高解像度化は別のリサイズ／アップスケール用ワークフローで対応します。
- **LLMの画像解析は初期設定でOFF**です。GUIの「画像をLLMで構図解析し、プロンプトに反映」をONにすると、画像対応VLMへ参照画像を送り、構図の説明を生成プロンプトに反映します。設定は `config.json` の `llm.send_reference_to_llm` に保存されます。
- I2Iは画像全体を描き直す方式です。特定部分だけをマスクして変更するInpaintingは未実装です。
- T2Iは従来どおり維持し、参照画像欄を空にすると戻せます。LLMにはノードの追加・削除・再接続を許可しません。


## 既存の設定を持っている場合

`config.json` はGit管理されません。初回GUI起動時に存在しなければ `config.example.json` から自動生成します。以前のOllama用 `config.json` がある場合は、GUIが **LM Studio設定を追加** して移行できます（既存のOllama設定を削除しません）。設定保存前に必要に応じて確認してください。

トークン認証を有効にしているLM Studioを使う場合、環境変数 `LMSTUDIO_API_TOKEN` にトークンを設定します。GUIにトークン文字列を保存しません。

## 安全性・制約

- LM Studio / ComfyUI はGUIから新たにインストール・起動せず、既存のローカルサーバーに接続します。
- 不正なワークフローID、API形式でないJSON、未登録ノードやパラメータ、範囲外の値は生成前に拒否します。
- モデルや仮想環境、キャッシュ、ローカル設定、生成画像はコミットしません。
- 他人のComfyUIジョブを削除・中断しません。複数実行する場合はGPU・VRAMの競合に注意してください。
- LM Studioの選択モデルを確実にアンロードできなければ生成を開始しません（アンロード設定ON時）。
- 出力プレビューはTkinterで表示できる形式を優先し、対応外の画像は保存ファイルを開いてください。
