# Comfy Orchestrator（asobiba / main）

用意済みの **ComfyUIワークフロー**を自然文から実行する、Windows向けローカルGUIです。LLMの解釈には **LM Studio** を標準採用し、追加のOllama導入は不要です。Python 3.11+ と標準ライブラリだけで動きます（Tkinterは通常のWindows版Pythonに同梱）。

## まずGUIを起動する

1. **LM Studio 0.4.0以降**を起動し、**Developer / Local Server** からサーバーを有効にする（標準ポート `1234`）。
2. ComfyUIを通常どおり起動する（標準ポート `8188`）。`waiIllustriousSDXL_v170.safetensors` がComfyUIに配置済みであること。
3. Windowsで `comfy-orchestrator/run_gui.bat` をダブルクリック。あるいはPowerShellから:

   ```powershell
   cd M:\asobiba\comfy-orchestrator
   python -m comfy_orchestrator.gui
   ```

4. GUIの **「モデルを更新」** からLM Studioにインストール済みのモデルを選ぶ。
5. **「接続確認」→「設定を保存」** で接続と設定を確認する。
6. 自然文を入力して **「解釈のみテスト」** でLLMの変換結果を確認。
7. 問題なければ **「画像生成を開始」** でComfyUIに投げる。

ウィンドウの右側に生成結果をプレビューし、画像は `comfy-orchestrator/outputs/` へ保存します（Git管理外）。日本語入力に対応しています。

### 画面で調整できる項目

- LM Studio / ComfyUI のURL、LLMモデル選択、接続確認と設定保存
- 固定ワークフローの選択（自動選択または明示選択）
- 自然文、参照画像（**I2I/I2Vの登録後に有効**）、解像度プリセット・幅・高さ・Steps・CFG・Seed
- LLM解釈だけのテスト、ComfyUI生成、実行ログ、出力画像の一覧とプレビュー
- **「待機を中止」** はクライアント側の待機だけを停止し、ComfyUIに投入済みの生成ジョブは停止しません。

画面の軽量初期値は **768×768 / 20 Steps / CFG 5.0** です。ユーザーがエクスポートした固定ワークフロー原本は **1024×1024 / 28 Steps / CFG 5.5** のまま保持しています。精細さが必要ならGUIで設定を変更してください。

**解像度プリセット:** 「生成パラメータ → 解像度」で、512×512、768×768、1024×1024、832×1216、1216×832、768×1024、1024×768、720×1280、1280×720から選択できます。選ぶと幅・高さへ反映されます。「カスタム」または幅・高さの手入力も可能です。保存・履歴復元時は既存の幅・高さを使用し、対応プリセットを自動表示します。I2I・部分修正は元画像の解像度を維持するため選択できません。出力寸法を指定できるポーズ参照では利用できます。

**Seedの扱い:** GUIのSeedが空欄なら、毎回アプリ側で安全な32bit乱数を生成します。Seedを明示入力した場合は、その値を優先して再現性を保ちます。LLMにはSeedの選択を任せず、不正なSeedを返しても採用しないため、LLM由来のSeed範囲エラーで画像生成が停止しません。


## 日本語入力・画面の見やすさ

GUIの入力欄を**コンパクトな6行のエディタ**に変更し、`Meiryo UI`・広めの行間・余白を採用しています。長い文章は欄内スクロールで入力できます。画面右上の **「ダーク表示」** で明暗を切替可能です。入力欄右上の `A−` / `A+` ボタンで**文字サイズを10～20pt**の範囲で調整できます。既存の入力文を消さずに切り替えられます。

色設定と文字サイズは「設定を保存」で `config.json` に保存され、次回起動時に復元します（Git管理対象外）。画像生成、ワークフロー、LLM解釈には影響しません。

**日本語IME変換中文字のフォント補正:** Tkinterでは、文字の確定前だけWindows IME側の別フォントで大きく表示されることがあります。Windows環境では入力欄にフォーカスしたときとIMEキー入力時に `ImmSetCompositionFontW`（Win32標準API）を使用し、入力欄と同じフォント名・サイズをIMEへ通知します。フォントサイズ変更にも追従します。IMEやWindows側の実装差で反映されない場合があるため、最終的な効果はWindows実機で確認してください。

**別問題：IMEの予測候補ウィンドウ**（「Tabキーを押して選択します」の一覧）はWindows側のUIで、上記の補正対象ではありません。必要な場合のみMicrosoft IMEの「予測入力」で別途設定してください。

## 起動時レイアウト・小さめの画面への対応

入力やポーズ参照の機能が増えても、**画面下部のボタンが見切れない**ようにレイアウトを変更しました。

- 初期ウィンドウサイズと最小サイズは、Windowsが通知する画面の幅・高さに合わせて決定します。従来の固定 `1240×910`／最小 `960×760` は使いません。
- 左側の**自然文・生成設定は独立した縦スクロール領域**です。マウスホイールか右端のスクロールバーで参照画像、部分修正、ポーズ参照まで移動できます。日本語の自然文エディタ内でのスクロールは従来どおりエディタが担当します。
- **「解釈のみテスト」「画像生成を開始」「待機を中止」**は入力欄の下に固定し、スクロール位置に依存しません。
- 右側の結果・履歴タブも、画像を開く／再生成／比較などの操作ボタンを下部に固定しました。
- **実行ログは初期状態で非表示**です。画面下の「ログを表示」ボタンで展開できます。ログを閉じても内容は保持し、新しい記録も追加されます。
- プレビュー画像は利用可能な領域に合わせて縮小表示します。画像の保存データ自体は縮小しません。

特にノートPCやWindowsの表示スケール125～150%で画面の有効高さが少ない環境を想定しています。マルチモニター環境や独自のタスクバー配置では、実際の表示領域に差があるため、必要ならウィンドウサイズを手動調整してください。

## T2I品質改善用プロンプト（v2 / 従来版比較）

GUIの生成設定に **「T2Iプロンプト」** を追加しました。WAI-Illustrious SDXLを使う通常T2I向けに、System Promptと画像なしの参照役割メタデータを切り替えます。他系列のT2IへIllustrious専用タグ規則は適用しません。

| モード | 内容 |
| --- | --- |
| `品質改善 (v2)`（初期値） | 自然文から主題・人数、外見、動作・姿勢、カメラと構図、背景、光源と陰影、描画品質を整理し、必要最小限のDanbooru系英語タグに変換。矛盾、過剰な品質タグ、不要な装飾を抑制 |
| `従来 (比較用)` | 以前の短いSystem Promptをそのまま使用。条件を揃えた比較用 |

変更したのは**LLMへの指示**です。ComfyUIの画像生成モデル・ノード構成、Sampler、Negativeの設定デフォルト、GUIの幅・高さ・Steps・CFG・Seedは変更しません。画像を伴うI2IやInpainting、ポーズ参照はこのT2I専用ルールの対象外です。

### 比較手順

1. **参照画像とポーズ画像を空欄**にして通常T2Iを選びます。幅・高さ、Steps、CFG、自然文と**固定Seed（例：12345）**を設定します。
2. `従来 (比較用)`を選び、**「解釈のみテスト」**を実行。Positive/Negativeのダイアログが開くので内容を確認・コピーします。必要に応じて「画像生成を開始」で結果を保存します。
3. **自然文と数値設定を変えず**、`品質改善 (v2)`に切り替えて、同じようにプロンプトと生成結果を確認します。
4. 履歴には生成時のT2I方式を保存します。過去の履歴データベースは非破壊で移行され、従来生成した履歴の方式が不明な場合はそのまま不明扱いです。

出力結果タブの **「生成タグを見る」** から、直近の生成・解釈テストで使ったPositive/Negativeを再表示・クリップボードへコピーできます。生成したプロンプトはログ（必要なら「ログを表示」）にも記録されます。

**品質改善の保証ではありません。** WAI系ではモデル・Sampler・画像解像度とタグの相性も影響します。長いタグ列を増やすだけでは品質が下がることもあるため、まず複数の題材で同じSeedの比較を行い、改善・悪化の両方を観察してください。新しい方式もLLMが指示を守らなければ生成品質は変わりません。

実装：`comfy_orchestrator/prompt_profiles.py`。設定：`config.json` の `llm.t2i_prompt_profile`（`illustrious_v2`／`legacy`）。旧設定には新しい初期値を追加し、既存のモデル名・ポート・トークン設定は保持します。

## 複数画像からキャラクター特徴を抽出・手動確定

抽出方式は、**完全一致する色・衣装などの集合**と、**異なる絵柄でも一貫して見える顔立ち・シルエット・デザイン上の特徴の仮説**を並列に扱います。画像に写っていない特徴は反証にはしませんが、明確に矛盾する画像は区別します。モデルが違う描き方を同じキャラの特徴として誤認する可能性は残るため、支持枚数・確信度は正解保証ではありません。


左側の **「キャラ参照 → 画像・特徴を編集...」** から、同一キャラクターの画像を **2～4枚** 追加します（PNG/JPEG/WebP、各20MB以下）。この参照は既存の「参照画像（I2I）」「構図参考（LLMのみ）」「ポーズ参照」とは**独立**しています。

**D&Dによる画像追加（Windows）:** エクスプローラーで複数の画像ファイルを選択し、メイン画面の **「キャラ参照」欄**、またはキャラ編集画面の**画像一覧**へまとめてドラッグ＆ドロップできます。メイン画面へ落とすと編集画面が開き、確定前の画像一覧に追加されます。空白や日本語を含むファイルパスに対応し、重複した画像は追加しません。対応していないファイル形式、存在しないファイル、上限4枚を超える一括追加はエラーとして拒否し、元の一覧はそのまま残します。画像を入れ替えた場合は以前の特徴抽出結果を破棄し、再抽出・再確定が必要です。

D&Dは追加の軽量Tk拡張 `tkinterdnd2`（`tkdnd`同梱）が必要です。GUIを起動する**同じPython**へ1回だけインストールしてください。

```powershell
py -3 -m pip install tkinterdnd2
```

`run_gui.bat` が `py -3` を使用できない環境では、代わりに `python -m pip install tkinterdnd2` を利用します。インストール後はGUIを再起動してください。未導入・ロード失敗の場合もGUIは起動し、従来の「追加...」ボタンで画像を選択できます。D&Dの対象は**キャラ参照一覧のみ**です。構図・I2I・ポーズ画像の入力欄は従来どおりファイル選択を使用します。

1. 画像対応モデルをLM Studioで選び、**「LLMで共通特徴を抽出」**を押します。画像を1枚ずつ観察したあと、観察文を突き合わせます。画像自体はまとめて送信せず、最後の統合はテキストだけで行います。
2. **「キャラの核（抽象的な特徴の仮説）」** と **具体的な共通特徴・部分一致・差分・不明点**を分けて表示します。顔の造形や目元、髪のシルエット、デザインの形状的傾向など、画風・衣装・角度が違っても残り得る特徴を、根拠画像と反証画像、LLM推定の確信度付きで示します。これは厳密な積集合ではありません。
3. 下の **「生成に使うキャラ説明」** には、反証がなく2枚以上の画像で支持された中・高確信度の抽象的な仮説と、全画像で一致した具体的特徴が**日本語の文章による修正用下書き**として入ります。支持枚数が少ない仮説・反証のある仮説・単なる差分は自動採用せず、根拠欄で参照します。誤認識を修正し、不要な特徴を削除してから **「修正内容を確定」** を押してください。確定前は生成に反映されません。
4. **「修正内容を確定」** を押すと以後のT2I/I2I（部分修正を含む）で、自然文とは別にキャラ特徴として渡します。ユーザーが今回指定した変更内容は優先されます。使用を止めるときは **「採用を解除」** を選びます。

**日本語の修正指示で書き直す:** 特徴抽出後は、文章を直接編集する以外に **「日本語の指示で修正...」** ボタンも利用できます。「目の色の記述を外して」「髪型はショートボブのままにして、説明を短くして」のように指示すると、選択中のLM Studioモデルが**現在の文章だけ**を入力として書き直します。修正処理に参照画像は再送しません。修正後もユーザーが編集欄を確認して **「修正内容を確定」** を押すまで、生成用のキャラ設定は変更されません。文章の修正案もLLMの誤解・過剰修正があり得るため、必ず内容を確認してください。

**日本語・自然文での修正:** 抽出LLMは画像の観察内容やキャラの核、根拠を日本語で返すよう指示しています。編集欄は英語のタグ羅列ではなく、たとえば「頬は丸みがあり、顎は小さい。黒いショートボブで、目尻はやや上がっている。」といった日本語の説明文です。普通の文章として書き換え・削除・追記できます。画像生成時には、この**確定済み日本語説明**を最後のプロンプト作成LLMに渡し、WAI用の英語タグへ変換させます。英語タグを書く必要はありません。なお、画像認識モデルによっては日本語指定に従わないこともあるため、その場合は編集欄で日本語へ修正してください。以前に保存した英語の確定特徴は**自動翻訳・上書きしません**。新方式を試すには改めて特徴抽出してください。



承認した特徴シートはローカルの `data/character_sheet.json` に保存され、次回起動時も復元します。画像の元ファイルを動かした場合は再選択してください。このローカル設定と画像の個人データはGit管理されません。**特徴抽出には画像対応VLMが必要**ですが、確定した特徴を文章として生成プロンプトに入れるだけなら画像対応モデルでなくても使えます。

生成履歴には **確定したキャラ特徴・LLMの観察結果・参照した画像をそれぞれコピーして保存**します。履歴タブで画像を選んで「生成タグを見る」→「キャラ特徴」から、生成時に採用したキャラ特徴と支持枚数を確認できます。履歴から設定を復元すると当時の確定特徴が戻り、同じSeedで再生成するときは**LLMによる特徴抽出を再実行しません**。

**VLMの形式違いへの対策:** LM Studioの小型VLMがJSONの`feature`に定義外の名前（例: `hair`、`face_shape`）を返しても、認識全体を即中断しません。特定できる別名は補正しますが、曖昧な項目・根拠画像番号の不正・内容が空の項目は**自動採用せず「要確認：形式不一致」欄へ内容とともに記録**します。有効な特徴と抽象仮説の抽出結果は維持します。エラーや不明項目の修正は編集欄で行ってください。これはモデルの視覚認識能力そのものを改善する機能ではありません。

**制約:** 支持枚数も抽象的な「キャラらしさ」の判断もLLMによる推定です。異なるイラストの目や衣装を誤って「共通」と判定したり、抽象的な印象をでっち上げたりする可能性があります。必ず編集画面で確認してください。また、複数画像を直接ComfyUIへ条件入力する機能ではありません。キャラクターの顔を厳密に固定するには、将来的に画像条件付けや専用モデルの検討が必要です。特徴抽出には、枚数分の画像観察と統合のLLM呼び出しが発生します。

## I2I / 部分修正の自然文プロンプト改善

生成設定に **「I2Iプロンプト」** を追加しました。通常I2I（`wai_i2i_basic`）と部分修正（`wai_inpaint_basic`）向けです。

| モード | 役割 |
| --- | --- |
| **保持重視 (v1)**（初期値） | 元画像で維持すべき要素とユーザーが変更したい要素を分けて解釈。無関係の服装・構図・背景・光源・人物数を勝手に変更しないよう指示 |
| **従来 (比較用)** | 以前のSystem PromptとUser Promptを維持 |

「髪だけ整える」「服のしわだけ自然に」「表情以外は維持」など、**変更範囲を限定した日本語指示**を優先します。Inpaintではさらに「マスク内だけに焦点を当て、外側を設計し直さない」という専用の指示を追加します。マスクの形状はLLMには通知されないため、**LLMがマスク内の画像内容を正確に理解できるわけではありません**。

Denoiseの設定値は変更しませんが、LLMへ生成前の補助情報として伝えます。

- `0～0.40`: `preserve-oriented`（元の絵を強く保つ）
- `0.40超～0.60`: `balanced`
- `0.60超～1.0`: `transform-oriented`

同じ自然文・Seed・Denoise・Steps・CFGで「保持重視」と「従来」を切り替えると比較できます。これはプロンプト改善であり、**I2Iの全画素や非指定部分を固定する機能ではありません**。非指定領域を確実に保持したい場合は、マスクを使った部分修正を利用してください。画像をLLMに見せない設定のときは元絵の具体的な衣装・姿勢・色を知ることはできず、記述を捏造しないよう指示しています。

### 履歴から実際のプロンプトを確認

**「生成履歴」**タブで生成結果を1件選び、下部の **「生成タグを見る」** を押します。生成当時に保存されたPositiveとNegativeをそのまま表示し、元の自然文、使用プロンプト方式、Seed・Steps・CFG・Denoiseを確認できます。両プロンプトは個別にコピー可能です。

履歴表示では**LLMを再実行せず、保存された `parameters_json` を読み出します**。追加のDB列は不要で、従来のT2I履歴でもプロンプトが保存済みなら表示可能です。過去の生成画像だけを取り込んだ旧履歴など、プロンプトが元から記録されていない項目については、存在しない文字列を補完せず「記録なし」と案内します。

今回追加したI2Iプロンプト方式は、既存の履歴DBの `prompt_profile` 列に記録します。履歴から設定復元した場合、記録があればI2I方式も復元します。既存のT2I方式と既存画像・履歴はそのまま保持します。

## LM Studioのトークン設定

標準値を **コンテキスト長8,192 tokens / 最大生成4,096 tokens** に設定しています。出力のばらつきは従来どおり `temperature=0.2` です。

- `config.example.json` の `llm.context_length=8192`：LM Studioのモデルを新規ロードするときのコンテキスト上限。
- `llm.max_tokens=4096`：`/v1/chat/completions` に渡す最大生成トークン数。**常に4,096トークン生成するわけではなく上限**です。
- 既存GUI設定が旧標準値の4,096コンテキスト・2,048出力だった場合は、次回のGUI起動時に新しい標準値へ一度だけ移行します。その後GUIで「設定を保存」または生成を実行すると、変更がGit管理外の `config.json` に保存されます。既に標準値以外を指定したユーザー設定は保護します。
- LM Studio側で既にモデルがロードされている場合は、そのモデルインスタンスのコンテキスト設定が優先されます。新しい8,192トークン枠を確実に使いたい場合は、LM Studio側で既存インスタンスをアンロードしてからGUIで解釈を実行してください。
- 推論用トークンの上限を増やすため、場合によってはLLMの計算時間やVRAM使用量が増えます。必要なら `config.json` で値を調整できます。

## LM Studioでタイムアウトする場合

Thinkingを使用するローカルLLMは、4,096 tokensの生成上限を活用すると解釈に4分以上かかることがあります。以前の `llm.timeout_seconds=240` は全APIで共通だったため、実際の応答が完成する前に通信が切れる場合がありました。

- `llm.inference_timeout_seconds=600`：LM Studioの **`/v1/chat/completions` だけ**に適用する通信待機上限（10分）
- `llm.timeout_seconds=240`：モデル一覧、ロード、アンロードなど従来のAPI操作用（4分）
- `comfyui.generation_timeout_seconds=1800`：画像生成の完了を待つ時間（従来どおり30分）

GUI起動時、既存のローカル `config.json` に新項目がなければ600秒を補完します。GUIの「設定を保存」で反映されます。手動で増減する場合はローカル `config.json` の `llm.inference_timeout_seconds` を編集してください（30～3,600秒）。

タイムアウト時は、どのLM Studio API操作で発生したか表示します。**延長しても確実に成功する保証はありません。** メモリ不足、モデルの応答停止、極端に低いtoken/s等でも応答が遅くなるため、再発する場合はLM Studioのログと実測速度を確認してください。自動リトライは行わず、重複実行を避けます。

## 生成履歴・画像比較・再生成

GUI右側に **「今回の結果」** と **「生成履歴」** のタブがあります。

- **履歴:** 生成成功時に元の日本語指示、LLMが決めたPositive/Negativeプロンプト、ワークフロー名、Seed、Steps、CFG、Denoise等をローカルSQLiteに保存。画像ファイルは従来どおり `outputs/` 内に保持します。
- **I2I元画像の保存:** 元画像を `data/references/` にコピーして参照するため、後から元ファイルを移動しても比較・再生成が可能です。
- **設定を復元:** 履歴を1件選んでボタンを押すと、自然文・ワークフロー・生成設定・参照画像を編集画面へ戻します。そこから文面を変えて新たに生成できます。
- **同じSeedで再生成:** 以前のPositive/Negativeと数値設定をそのまま再利用し、LLMを呼び出さずComfyUIで再実行します。画像のピクセル完全一致を保証するものではありません。
- **別Seedで再生成:** プロンプトなどは維持したままSeedのみ乱数に変更します。
- **画像比較:** I2I履歴を1件選ぶと「元画像 / 生成結果」、T2I履歴をCtrl+クリックで2件選ぶと「生成結果A / B」を並べて比較できます。比較ウィンドウには連動した倍率変更とスクロールがあります。
- **過去の出力:** この機能の追加前に `outputs/` にあった画像は、既知のファイルのみ「旧画像（設定不明）」として取り込みます。古い設定は復元できないため、履歴からの再生成ボタンは使用できません。

保存先は `comfy-orchestrator/data/history.sqlite3`、I2I参照元のバックアップは `data/references/`、出力画像は `outputs/`。どれもGit管理外です。履歴の削除機能はまだありません。アプリは個人利用のローカル履歴として扱い、クラウドへの同期は行いません。

**表示形式:** 標準のTkinterでPNGを比較できます。JPEG/WebPの元画像を比較する場合や滑らかな任意倍率の拡大縮小には、任意で `python -m pip install Pillow` を実行してください。PillowはGUI起動や画像生成には必須ではありません。

## 画像からI2I・部分修正・ポーズ参照（追加機能）

### 自動切替

- **参照画像が空、ポーズ画像も空** → 自動的に `wai_t2i_basic`（T2I）を選択します。直前がI2Iや部分修正でもT2Iへ戻ります。
- **参照画像を選択** → `wai_i2i_basic`（通常I2I）へ切替。
- **参照画像を選択し「範囲を塗る...」でマスクを確定** → `wai_inpaint_basic`（部分修正）へ切替。マスクを消すと通常I2Iに戻ります。
- **ポーズ参照を選択** → `wai_pose_skeleton` または `wai_pose_detect`（ポーズのみを使ったT2I）へ切替。通常I2Iの元画像とは排他です。ポーズ参照を消すと通常T2Iへ戻ります。

「今回の結果」の「この画像からI2I」、または履歴で1件選択して「選択した画像をI2Iの元画像にする」を押すと、生成済み画像を直接次のI2I入力にできます。

### 部分修正（Inpainting）

1. 元画像、または生成結果からI2I入力を選びます。
2. **「範囲を塗る...」** を開き、修正したい領域だけを赤色のブラシで塗ります。Undo・全消去が可能です。
3. **「この範囲を使う」** で元解像度の白黒マスクをローカル保存します。**白＝描き直す／黒＝元画像を維持する**。
4. 自然文に「手の指を自然に修正する」などと入力し、通常どおり生成を実行します。

ワークフローはComfyUI標準の `LoadImageMask`、`VAEEncodeForInpaint`、`ImageCompositeMasked` を利用。**未指定領域のピクセルを元画像から戻す構造**ですが、マスク境界は不自然になる可能性があります。必要ならマスクを少し広げて調整してください。一般SDXLチェックポイントを使う簡易Inpaintingであり、専用Inpaintモデル相当の保証はありません。

**必要な追加Pythonパッケージ**：GUIのマスク描画のみ `Pillow` が必要です。通常のT2I/I2Iには不要。GUIを起動するPythonに次を実行：

```powershell
python -m pip install Pillow
```

### 構図認識の二段階処理（画像対応VLM）

構図の取り違えを見つけやすくするため、構図解析ON時のLM Studio処理を2段階に分けています。

1. **画像観察:** 画角、カメラ視点、人物の数・位置、姿勢と重心、胴体の向き、頭部・視線、左右の腕と手、脚と足、見えない／不明な部分を、画像から事実として項目別に抽出します。見えない関節は`unknown`と表記するよう指示します。
2. **プロンプト生成:** 観察結果を別のテキスト入力としてLM Studioに渡し、ユーザーの自然文と統合して英語の生成プロンプトにします。**画像自体は2回目には再送しません。** 2段階を終えてからLM Studioのモデルをアンロードし、ComfyUIに生成を任せます。

画像をセットした状態で**「解釈のみテスト」**を実行すると、構図の認識結果がログに記録されます。GUIの**「認識結果...」**ボタンからも確認できます。モデルが「右腕が見えない」「視点が不明」等と答えた部分は、ユーザーの生成指示で補ったり、OpenPose ControlNetを利用したりしてください。

**注意:** 2回のLLMリクエストとなるため、従来より解釈に時間がかかります。分割により認識の根拠は見えますが、モデルの視覚能力そのものは改善せず、左右の取り違えや見えない部位の誤推定は依然起こり得ます。構図の厳密な再現を優先する場合はControlNetやポーズ画像を使用してください。

### 構図参考画像だけからT2I（ControlNet不要）

**「構図参考（LLMのみ）」** は、通常の「参照画像（I2I）」や「ポーズ参照（ControlNet）」と独立した欄です。DesignDollの通常のスクリーンショットや既存イラストを指定すると、**画像対応LM Studioモデルがカメラ視点・人物配置・ポーズ・トリミング等を文章で読み取り、T2IのPositiveプロンプトに反映**します。構図参考の画像自体はComfyUIには送信しません。

1. LM Studioのモデル一覧から画像対応VLMを選択します。
2. **「構図参考（LLMのみ）」→「参照...」**でPNG/JPEG/WebPの画像を選択。GUIの「画像をLLMで構図解析し、プロンプトに反映」が自動でONになります。
3. 通常の「参照画像」と「ポーズ参照」は空欄にしておくと、**自動で通常T2I**が選択されます。
4. 日本語で「この画像の構図と視点を使い、キャラクターは白い服の少女にして」などと入力。まず「解釈のみテスト」で構図のタグを確認し、生成します。

通常I2Iと併用する場合は、通常の「参照画像」に元絵を、こちらに構図画像を別々に設定できます。ただし、最終的な位置関係は**文章指定のみでは厳密には固定されません**。マネキンのポーズの忠実な再現には、従来のOpenPose ControlNetのほうが強い制御です。

この画像はローカルのLM Studioにのみ送信され、生成履歴にはコピーを保持します。過去の履歴も非破壊でデータベース移行します。構図指定はPositiveプロンプトに含まれるため、同じSeedでの再生成は画像解析やLLMロードなしで実行できます。

### 画像対応LLMで構図を解析してプロンプトに反映

画像を読み込んで生成する場合、左の設定欄にある **「画像をLLMで構図解析し、プロンプトに反映」** をONにできます。ローカルのLM Studioから**画像入力に対応したVLM**を選択してください。通常の文章専用LLMは画像を解析できません。

- **I2I／部分修正**：元画像をLLMへ渡し、カメラアングル、画面内の人物の位置、構図、視線、身体の向き、トリミング、奥行きなどを解析。ユーザーが入力した変更指示を尊重し、具体的な英語タグをPositiveプロンプトへ追加します。
- **ポーズ参照**：DesignDoll等の通常画像、またはOpenPose骨格PNGをLLMにも渡します。**参照するのは視点・ポーズ・人物配置のみ**と指示し、マネキンの材質、服の色や背景は生成にコピーしません。生成時の画像は別途ControlNetへ送られます。
- **画像指定なしのT2I**：「構図参考」も空欄なら画像はLLMに送信せず、従来の文章入力のみで生成します。
- **モデルの確認**：LM Studioのモデル一覧で`capabilities.vision=false`が明示されたモデルは、画像を渡す前に拒否します。未報告のモデルは推論時に対応可否が判定されます。
- **OFFの場合**：従来どおり画像をComfyUIだけに送信し、LLMは日本語指示を文章から解釈します。

例：「この人形の**構図・カメラ視点・ポーズのみ**を参考に、白いワンピースの少女を描いて。背景は海辺。」と入力します。実際にLLMが生成した構図指定は「解釈のみテスト」のログから確認できます。

**制限：** LLＭが生成するのは**文章による構図指定**であり、画像内の関節位置や座標を正確に固定するものではありません。精密なポーズ・構図保持にはOpenPose ControlNetと併用してください。画像の解析はテキストのみの場合より時間とメモリを使うため、生成前にLLMをアンロードする既存の処理を維持します。画像は設定したローカルLM Studioサーバーへ送信されます。

### DesignDoll / 人物画像のポーズのみ参照

**2種類の入力モード**があります。

- **骨格PNGを直接利用**：OpenPose形式（黒地に色分けされた骨格線）の画像を指定。すでに骨格化されているため、外観・服の色などは読み込まず、ポーズ制御に使います。`wai_pose_skeleton`。
- **通常画像から骨格検出（DWPose）**：DesignDollの人形スクリーンショットや人物画像を指定。DWPoseで関節位置を抽出してからControlNetへ渡します。`wai_pose_detect`。被写体や関節の隠れ方によって誤検出する場合があります。

どちらのモードも **追加モデルの導入が必要** です：

1. SDXL OpenPose ControlNet [xinsir/controlnet-openpose-sdxl-1.0](https://huggingface.co/xinsir/controlnet-openpose-sdxl-1.0) から `diffusion_pytorch_model.safetensors` を取得。必要なら `controlnet-openpose-sdxl-1.0.safetensors` とリネームして、`ComfyUI/models/controlnet/` へ配置します。**ワークフローはこのリネーム後のファイル名を参照**します。ComfyUIを再起動してください。
2. 通常画像から骨格を推定する場合は、ComfyUI-Managerで [comfyui_controlnet_aux](https://github.com/comfyorg/comfyui-controlnet-aux) をインストール。DWPose関連の検出モデルも使用します。
3. GUIの「ポーズ強度」で制御の強さを調整（初期0.85）。幅・高さは通常のT2I同様に変更できます。

参照用のSDXL ControlNetは約2.5GBの追加モデルです。16GB VRAMでは通常のI2Iより計算・メモリ負荷が増すため、最初は768×768・20steps程度で動作確認してください。**モデルはこのアプリから自動ダウンロードしません。** 不足しているモデルやDWPoseノードは生成前にエラー表示します。Illustrious SDXLとの互換性・ポーズの再現度は実機検証が必要です。

### 履歴との連携

部分修正時の**元画像とマスク**、ポーズ参照時の**入力ポーズ画像**は、生成履歴にそれぞれ保存されます。以前の履歴DBも自動移行し、画像を変えずに再生成できます。複数案生成は今回追加していません。

## 実行時のモデル解放とPC負荷

```text
日本語入力
  ↓
LM Studioの指定LLMをロード（すでにロード済みなら再利用）
  ↓
LLMが固定ワークフローと許可された入力をJSONで決定
  ↓
LM Studio APIで、そのLLMインスタンスのアンロード完了を確認
  ↓
ComfyUIへ固定ワークフローをキュー投入
  ↓
ComfyUIで画像生成 → 出力取得・表示
```

GPUメモリ節約のため、GUI初期状態で「LM Studioモデルを解釈後にアンロード」がONです。**選択したモデルがLM Studioの画面で事前ロードされていても解放します。** 別のLLMを巻き込んでアンロードしません。ComfyUI側の前回モデルの解放は、キューが空の場合に限って要求します。

実際のVRAM解放量は各プロセス・GPUドライバーに依存します。ComfyUIの `/free` は非同期要求であり、完全解放の保証ではありません。必要なモデルファイルのロード時間は発生します。

## 既存の固定ワークフロー

| ID | 種類 | API JSON |
|---|---|---|
| `wai_t2i_basic` | T2I / アニメイラスト | `workflows/wai_t2i_basic.api.json` |
| `wai_i2i_basic` | I2I / 参照画像から描き直し | `workflows/wai_i2i_basic.api.json` |

`config.example.json` には、ノードIDと入力の対応を登録済みです。I2Iは元画像を`LoadImage (16)`で読み込み、`VAEEncode (17)`を通して`KSampler (11)`へ送る構成です。元の出力設定のDenoiseは `0.53` です。

### I2Iの使い方（Windows GUI）

1. **参照画像** からPNG/JPEG/WebPを選択します。画像が選ばれるとワークフローが `wai_i2i_basic` に自動切替されます。
2. 日本語で「服の色を青に」「表情を笑顔に」など変更内容を入力します。
3. **Denoise (I2I)** を調整します。目安は `0.3`（原形を強く維持）～ `0.7`（大きく描き直し）で、初期値は `0.53` です。
4. 「解釈のみテスト」で指示の変換を確認し、「画像生成を開始」でComfyUIに送ります。

- **I2Iの出力解像度は参照画像と同じ**です。元画像が224×224なら生成も224×224です。GUIの幅・高さはI2Iで無効化します。高解像度化は別のリサイズ／アップスケール用ワークフローで対応します。
- **LLMの画像解析は初期設定でOFF**です。GUIの「画像をLLMで構図解析し、プロンプトに反映」をONにすると、画像対応VLMへ参照画像を送り、構図の説明を生成プロンプトに反映します。設定は `config.json` の `llm.send_reference_to_llm` に保存されます。
- I2Iは画像全体を描き直す方式です。特定部分だけをマスクして変更するInpaintingは未実装です。
- T2Iは従来どおり維持し、参照画像欄を空にすると戻せます。LLMにはノードの追加・削除・再接続を許可しません。

## 安全性・制約

- LM Studio / ComfyUI はGUIから新たにインストール・起動せず、既存のローカルサーバーに接続します。
- 不正なワークフローID、API形式でないJSON、未登録ノードやパラメータ、範囲外の値は生成前に拒否します。
- モデルや仮想環境、キャッシュ、ローカル設定、生成画像はコミットしません。

- LM Studioの選択モデルを確実にアンロードできなければ生成を開始しません（アンロード設定ON時）。

## I2V：静止画から動画を生成（Wan2.2 TI2V 5B）

ComfyUI標準のWan2.2 5Bワークフローを登録済みです。通常のI2Iとは明示的に切り替えます。最新のComfyUIが必要です。モデルは以下の3ファイルをComfyUIのmodels以下に配置してから再起動してください。既存モデルは削除しません。

| 保存フォルダ | ダウンロード |
| --- | --- |
| diffusion_models | [wan2.2_ti2v_5B_fp16.safetensors](https://huggingface.co/Comfy-Org/Wan_2.2_ComfyUI_Repackaged/resolve/main/split_files/diffusion_models/wan2.2_ti2v_5B_fp16.safetensors) |
| text_encoders | [umt5_xxl_fp8_e4m3fn_scaled.safetensors](https://huggingface.co/Comfy-Org/Wan_2.1_ComfyUI_repackaged/resolve/main/split_files/text_encoders/umt5_xxl_fp8_e4m3fn_scaled.safetensors) |
| vae | [wan2.2_vae.safetensors](https://huggingface.co/Comfy-Org/Wan_2.2_ComfyUI_Repackaged/resolve/main/split_files/vae/wan2.2_vae.safetensors) |

公式参考: [Wan2.2 5B workflow](https://github.com/Comfy-Org/workflow_templates/blob/main/templates/video_wan2_2_5B_ti2v.json) / [ComfyUI documentation](https://docs.comfy.org/tutorials/video/wan/wan2_2).

1. ワークフローで `wan22_i2v_5b` を選択し、参照画像を1枚指定（または生成結果・履歴の「I2Vに使用」）。マスク、ポーズ、構図参考画像は空欄にする。
2. 動画サイズ、フレーム数、FPS、Steps、CFG、Seedを指定。初回は832×480・49フレーム・24fps・20 Stepsを推奨。縦長は480×832、正方形は640×640。元画像と異なる縦横比では中央クロップされる場合があります。
3. 「髪が風になびく。まばたきして微笑む。カメラは固定。」等の動きを自然文で指示。LLMは動画用の英文を作り、技術設定はGUIが決定します。
4. 「動画生成を開始」。結果はComfyUIとアプリのoutputsにMP4として保存されます。GUIの「ファイルを開く」または履歴の「開く」でOS既定プレイヤーを起動します（GUI内の動画再生は未実装）。履歴復元・Seed再生成に対応します。

動画生成は静止画より大きなVRAM・RAM・時間を必要とします。16GB GPUでの動作を保証するものではありません。まず49フレームで実測してください。動画の待機上限は既定7200秒（`comfyui.video_generation_timeout_seconds`）、静止画は従来設定のままです。動画取得上限は512MiBです。LLMは従来どおり生成前にアンロードします。


## I2V本命：MiniMax H3 FL2VA（ローカル・音声付き）

「I2Vに使用」は `minimax_h3_i2v` を選択します。従来の `wan22_i2v_5b` もワークフロー選択欄から引き続き利用できます。H3は最新のComfyUI（ネイティブH3対応に加えてINT8 ConvRot対応のPyTorch CUDA 13.0環境を推奨）が必要です。モデルのダウンロード・配置は一度だけ手動で行います。

| ComfyUI/models 以下の配置先 | ファイル |
|---|---|
| diffusion_models | [minimax_h3_fl2va_pruned_int8_convrot.safetensors](https://huggingface.co/Comfy-Org/MiniMax-H3/resolve/main/diffusion_models/minimax_h3_fl2va_pruned_int8_convrot.safetensors) |
| text_encoders | [qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors](https://huggingface.co/Comfy-Org/MiniMax-H3/resolve/main/text_encoders/qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors) |
| vae | [minimax_h3_video_vae_int8_convrot.safetensors](https://huggingface.co/Comfy-Org/MiniMax-H3/resolve/main/vae/minimax_h3_video_vae_int8_convrot.safetensors) |
| vae | [minimax_h3_audio_vae_fp32.safetensors](https://huggingface.co/Comfy-Org/MiniMax-H3/resolve/main/vae/minimax_h3_audio_vae_fp32.safetensors) |

公式の[ローカルI2Vテンプレート](https://github.com/Comfy-Org/workflow_templates/blob/main/templates/video_minimax_h3_i2v.json)の通常20ステップ経路をAPI形式に展開しています。Turbo LoRA、Ref2VA、終点画像入力、2K再生成は今回の対象外です。H3のNVFP4 AWQテキストエンコーダはBlackwell専用ではありません。約37.3GBのモデルを使用するため、16GB VRAMではCPUオフロードが必要です。

最初は864×480、約5秒（124f）、20 steps、24fps固定を推奨します。約8、10、12、15秒も選択できます。長尺では0.4MP前後から試してください。縦横比は元画像に近いプリセットを選択してください（ネイティブのfirst_frameは指定解像度へ変形します）。CFGとnegative promptはH3のBasicGuider経路では使用しません。LM Studioには動画の長さも渡し、動き・時間展開・音の指示を自然な英文に変換します。

H3の動作が重い場合は、既存Wanを軽量プレビュー用に利用してください。実機でのVRAM使用量、速度、生成品質は未確認です。詳細は[ComfyUI公式ガイド](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-native)と[モデル配布元](https://huggingface.co/Comfy-Org/MiniMax-H3)を参照してください。

### H3専用プロンプト方式

`minimax_h3_i2v` 選択時に「プロンプト方式」が表示されます。既定値は「イラストの画風維持」です。

| 方式 | 用途 |
|---|---|
| 汎用動画 | 従来のH3プロンプト（比較用） |
| イラストの画風維持 | 元絵の線、塗り、陰影、色、デザインを維持しながら指定箇所を動かす |
| 2Dセル画アニメ | 輪郭線と色面、セル影、明確なキーポーズを重視する |
| Live2D風の微動 | 指定された呼吸、瞬き、表情、髪や服などの小さな動きに集中する |
| アクションアニメ | 指定動作の予備動作、重心、加減速、フォロースルーを整理する |

変更対象はLM Studioのプロンプト解釈のみです。解像度・FPS・フレーム数・Steps・Seed・ノード・モデルは変更しません。別のLoRAも不要です。ユーザーが明示した動き・画風・音声を優先し、指示にない動きやセリフ、カメラ移動を勝手に追加しないよう指示します。

選択方式は設定保存時に `llm.h3_prompt_profile` へ保存し、次回起動時に維持します。生成履歴・プロンプト表示にも使用した方式を記録し、設定復元時に選択を復元します。プリセット導入前のH3履歴は方式「記録なし」のまま保持し、設定復元では従来の汎用動画を選択します。保存済みプロンプトによるSeed再生成はLLMを呼ばず、元のプロンプトをそのまま使用します。

品質や画風保持を保証する機能ではありません。同じ入力画像、指示、解像度、フレーム数、Steps、固定Seedを用い、まず「解釈のみテスト」で英文を確認した上で、汎用動画と目的のプリセットを比較してください。

## 共通生成画面

画像・動画とも1画面で操作します。上部のLLMモデル選択、ワークフロー、プロンプト、参照画像、生成設定、結果/履歴は共通です。ワークフロー名は用途別の日本語表示ですが、設定と履歴には従来通り内部IDを保存します。

- URL・解放設定・ダーク表示・接続確認・設定保存は上部「設定」を展開。
- 「参照画像」は常時利用できます。従来どおり参照画像・マスク・ポーズで静止画のワークフローを自動選択し、動画はワークフロー欄で選択します。
- 「追加参照」で構図参考とポーズを展開。選択済みの参照は折りたたみ後も表示し、解除できます。キャラ参照はボタンで開きます。
- 解像度、フレーム数/長さ、Steps、CFG、Seed、Denoise、ポーズ強度、プロンプト方式は共通設定欄内で必要な項目だけ表示します。静止画の幅・高さを編集するには解像度「カスタム」を選択してください。元画像サイズのI2Iでは解像度は表示のみです。動画の24fps等の情報は関連フィールドのラベルに集約します。
- 結果が1件の場合は一覧を隠します。画像の場合のみI2I/I2V転用を表示し、動画は「開く」で再生します。詳細プロンプトは「プロンプト」から確認できます。履歴の同/別Seed再生成、比較、復元は従来通りです。

### 応答性の対策

- 参照や解像度の入力途中に同じレイアウトを繰り返し適用しない。キャンバス幅・スクロール範囲も値が変化したときだけ反映する。
- 履歴のDB取得・既存画像の探索はワーカースレッドで実行し、Tk側は変更行だけ更新する。通常の生成完了時は既存ファイル全体を再探索しない。
- 結果タブの表示中は履歴プレビューを読み込まない。同じ履歴を選択した場合の再デコードを避ける。

### MiniMax H3 モデル・Turbo切替

共通生成画面で MiniMax H3 を選ぶと「モデル」「Turbo」を表示します。INT8 ConvRot / W4A8 Mixed の両方で OFF / 8 Steps / 4 Steps を選べます。OFFではH3専用のStepsを入力でき、Turboでは対応するステップ数が固定されます。静止画・Wan用のStepsは変更しません。初期値は従来のINT8・OFFです。

追加ファイル（既存のテキストエンコーダー・VAEは共用）:

- `models/diffusion_models/minimax_h3_fl2va_pruned_w4a8_mixed.safetensors`: https://huggingface.co/Kijai/MiniMax-H3-experimental
- `models/loras/minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors`
- `models/loras/minimax_h3_fl2v_turbo_4step_v1.3_768p_comfyui_bf16.safetensors`
- LoRA配布元: https://huggingface.co/lightx2v/Minimax-h3-Turbo

ComfyUI公式FL2VAテンプレートと同じModelOnly LoRA（strength 1.0）、simple scheduler、res_multistepを使用します。8/4ステップはLoRAの名称に合わせた固定値です。W4A8とTurboの組み合わせは実機で比較してください。未導入モデル・LoRAはLLM推論前に確認します。新規履歴はモデルとTurbo選択も保存し、同Seed/別Seed再生成は保存した組み合わせを復元します。旧履歴には未記録の設定を追記せず、従来のグラフを再利用します。GGUF・その他派生モデルはこの変更の対象外です。
