作成日: 2026-11-28  
状態: 計画のみ・着手保留

基準コミット: `488df04d245b37189e0733e99abb9eebaccda187`

## 1. 目的と範囲

自宅の PC で動作する asobiba を、**外出先のスマートフォン（4G/5G・外部 Wi-Fi）から操作できるようにする。外出先からの利用を初期版の必須要件とし、家庭内 LAN は同じ方式での動作確認にも利用する。**スマホ側には画像生成モデルや LLM を導入せず、計算・ファイル保存は既存の PC 側で行う。Android のブラウザを初期対象とし、特定 OS の専用アプリを必須としない。

- **ユーザーから改めて着手指示があるまで、コード変更、サーバー起動、ポート開放、依存関係追加は行わない。**
- 既存の Tkinter GUI は維持する。全面的な Web 化やモバイル専用アプリの開発は今回の計画外。
- 初期版は外出前に自宅 PC を起動し、asobiba GUI・LM Studio・ComfyUI・プライベート VPN を利用可能な状態にする。画面ロックやモニター消灯中も動作することを検証する。PC の電源 OFF、スリープ、休止状態では原則として生成できない。外出先からの起動、ログアウト/再起動後の無人復旧は別段階とする。
- 画面サイズの小さい端末では編集操作を絞る。生成指示、状態確認、結果閲覧・再生成を優先する。
- 新モデルの導入は別計画とする。スマホ操作基盤は既存の登録済みモデルで検証し、新しいモデルごとにスマホ UI を作り直さない。

## 2. 操作方式

PC 側の asobiba に任意起動の Web 操作用インターフェースを設け、プライベート VPN 経由でスマホブラウザから接続する。第一候補は Tailscale + Tailscale Serve（tailnet 限定 HTTPS リバースプロキシ）。PC とスマホの双方に VPN クライアントを導入し、認証した端末のみ接続を許可する。asobiba 専用の配布アプリ、ストア審査、生成用クラウドサーバーは不要。VPN のアカウント登録・接続調整サービスは利用する。外部サービスを採用するかは着手時にユーザーが承認する。HTTPS 接続とブラウザの要件を満たせる場合は、後からホーム画面追加・PWA 化を検討する。

```
PC GUI (Tkinter)          外出先スマホブラウザ
       │                        │
       │               4G/5G・外部 Wi-Fi
       │                        │
       │           プライベート VPN + HTTPS
       │                        │
       │                 認証済み Web API
       └─────────┬──────────────┘
                 ▼
      共通ジョブ受付・実行管理
       （1 GPU / 順次実行）
                 │
      GenerationController
          ┌──────┴──────┐
          ▼             ▼
      LM Studio       ComfyUI
          └──────┬──────┘
                 ▼
         履歴・生成結果・素材
```

スマホから ComfyUI/LM Studio に直接接続させない。既存のプロンプト解釈、思考設定、モデル登録、画像調整、比較生成、生成履歴、トークン計測、キャッシュ、ジョブ回収を共通のバックエンド経由で利用する。

## 3. 初期版の画面・機能

| 画面 | 必須機能 | 後回し |
|---|---|---|
| 生成 | 日本語指示、画像モデル選択、LLM 思考 OFF/ON/自動、解像度、Seed（任意）、生成開始 | すべての高度なモデル設定 |
| 実行状況 | 解釈中・生成中・結果回収・完了・エラー、経過時間、対象ジョブの中止要求 | 複雑なスケジューリング |
| 履歴 | 既存履歴と共通のサムネイル一覧、画像の拡大・端末への保存、元指示、同条件/別 Seed の再生成 | 大規模な一括管理 |
| 設定 | 自宅 PC の到達可否、生成サービスの稼働状況、切断・セッション管理 | モデル登録、ComfyUI/LM Studio の接続先書き換え、サーバー管理 |

縦画面を基本に、生成・実行状況・履歴の3画面を切り替える。通常生成は入力欄とモデル選択を中心とし、詳細設定は折りたたむ。生成結果の画像は一覧で縮小表示し、タップして元画像を確認できるようにする。PC の既存 GUI をそのまま狭い画面へ移植しない。

## 4. 実行管理と既存コードへの接続

現状の `generation_controller.py` は Tk 非依存の生成サービス、`task_controller.py` は単一のフォアグラウンド操作と UI イベントの管理を担当する。比較生成は `model_comparison.py` で既に順次実行する構成になっている。したがってスマホ専用の生成エンジンは作らない。

- 共通のジョブ受付・実行状態を GUI から独立したサービスへ抽出する。初期実装は既存 PC GUI と同一プロセス内で Web サーバーを起動する方式を候補とする。HTTP スレッドから Tk を直接操作しない。
- PC/スマホで一つの実行権を共有し、LLM のロード・アンロード、ComfyUI のメモリ解放、モデル切替を競合させない。初期版は実行中の追加生成を明示的に拒否し、待ち行列は第2段階で必要性に応じて追加する。
- リクエスト受付時に設定・参照素材・モデル・思考設定を確定し、クライアントからの編集で実行中の設定が変わらないようにする。生成の開始/停止はジョブ ID を明示する。
- HTTP の応答は受付 ID と状態を返す。LLM 推論が20分かかる場合でも、HTTP 接続をその間保持しない。短い状態取得（初期版はポーリング）で進捗を表示し、必要なら後から SSE を追加する。
- ブラウザを閉じる、スマホがスリープする、4G/5G と Wi-Fi が切り替わる、通信が一時切断される、といった事象だけで生成を中止しない。再接続時に同じジョブ ID の状態を取得する。
- 二重タップ・再送時は idempotency key とサーバー側の記録で重複投入を防止する。ComfyUI の応答が不明な場合は既存ジョブ記録から回収し、自動で再投入しない。
- ジョブ履歴・生成画像・比較グループ・トークン使用量は既存の保存先を共有する。別のスマホ用履歴 DB を作らない。スマホからの生成完了を PC 側にも反映する。
- 初期版の Web API は既存の許可済みモデル/ワークフローを列挙し、生成受付、状態取得、中止、ページ分割した履歴、サムネイル/原寸の取得、再生成を提供する。ファイルパスや任意の ComfyUI グラフ、任意 URL、任意コマンドを受付可能にしない。

## 5. ネットワークとセキュリティ

外出先アクセスを前提に、公開インターネット上へ生成サービスを直接公開しない。VPN に接続できる端末も無条件に信頼しない。

- スマホ操作サーバーは既定で停止。PC GUI から明示的に有効化したときだけ起動し、接続先と稼働状況を表示する。第一候補の Tailscale Serve を使う場合、asobiba の Web サーバーは 127.0.0.1 にのみ bind し、Serve 経由で tailnet 内に限定して HTTPS 接続を受ける。Grants/ACL で認証済みユーザー・端末から必要な Web サービスポートへの通信だけを許可し、Windows Firewall でも直接到達を防ぐ。Tailscale Funnel（公開インターネット向け）は使わない。別 VPN を採用する場合も同等のアクセス制限を必須とする。
- スマホと PC の間は VPN 暗号化および認証付き HTTPS を原則とする。Tailscale Serve を採用する場合は HTTPS 証明書と DNS 名を使用する。証明書発行に伴う端末名の公開情報（Certificate Transparency）も確認する。Serve から同一 PC の loopback への内部転送を除き、平文 HTTP で認証情報・画像・生成指示を常用しない。証明書警告の無視を運用手順にしない。
- PC に表示する有効期限付きの一回限りのペアリング情報を用い、認証済みセッションを発行する。初回ペアリングは PC 側で承認し、失効・接続解除・試行回数制限を設ける。QR コードを採用する場合も長期認証情報を URL に入れない。
- 認証は全 API と画像配信に適用する。同一オリジン制約、Origin/Host 検証、CSRF 対策、セッション Cookie の安全な属性を設け、任意サイトから生成要求を送れないようにする。
- 画像は履歴 ID と許可済み画像 ID で参照し、保存領域外のパスを解決させない。任意ファイル一覧やディレクトリ参照は提供しない。将来の画像アップロードも拡張子だけで信用せず、実形式、ファイルサイズ、画素数、保存先を検証する。
- LM Studio、ComfyUI は従来の PC 内部向け接続を維持する。ルーターのポート転送、UPnP、公開トンネルは使わない。スマホ利用目的のために生成バックエンドをインターネットへ直接露出させない。
- Tailscale は第一候補とするが、導入・アカウント登録・証明書有効化・ネットワーク設定変更はユーザー承認後とする。VPN を採用してもアプリ認証は省略しない。VPN の直結経路が確立しない場合は暗号化された中継接続となることがあり、動画・大画像の転送速度が低下し得る。サムネイルを優先し、原寸画像は明示操作時のみ取得する。スマホ紛失時は VPN の端末権限とアプリセッションの両方を失効可能にする。
- パスワード・トークン・セッション情報・参照画像を Git やログに保存しない。ブラウザ向けエラーからローカル絶対パス等の情報漏えいを避ける。

## 6. 外出前の準備と無人運用

初期版の運用は、外出前に PC の電源、VPN、LM Studio の Local Server、ComfyUI、asobiba の Web 操作機能を確認する方式とする。長時間のアイドル時に PC がスリープしないよう、ユーザーが電源設定を確認する。ロック中の GPU 推論と動画/画像の回収を実機で検証する。OS やモデルサーバーが停止したときの不在中の復旧は初期版では保証しない。

- 出発前チェック画面に VPN 到達性、生成サービス接続、GPU 使用可否、ディスク空き容量を表示する計画とする。自動で電源設定やファイアウォールを書き換えない。
- 外出先では PC 到達不能と、PC 到達可能だが生成サービス停止/エラーを区別する。
- 後続段階で起動ランチャー、Windows ログイン時の自動起動、ヘッドレス運用を検討する。Tailscale の Windows Run unattended は VPN の接続維持だけを担い、asobiba、LM Studio、ComfyUI の自動起動や復旧を保証しない。
- Wake-on-LAN は必要性が確認された場合のみ検討する。停止・スリープ中の PC 自身は VPN 経由で応答できないことがあるため、LAN 内の常時稼働中継機器、NIC/UEFI、電源状態、復帰後のサービス起動等の条件が必要。WAN へのポート転送で代替しない。現時点では対応可否未確認。

参考（2026-11-28 確認）: [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve) / [Access control](https://tailscale.com/docs/features/access-control) / [Connection types](https://tailscale.com/docs/reference/connection-types) / [Windows Run unattended](https://tailscale.com/docs/how-to/run-unattended)

## 8. 検証・採否

- Android ブラウザの縦画面（360～430 CSS px 程度）で操作、スクロール、日本語入力、画像拡大、端末への保存を確認する。
- スマホの Wi-Fi を切り、4G/5G 経由で VPN に接続して認証・生成・履歴取得を実施する。外部 Wi-Fi、回線切替、中継経路での画像取得、PC の画面ロックも検証する。VPN を切った状態や未許可端末からはサービスにアクセスできないことを確認する。
- PC/スマホから同時に生成を要求しても、一方のみが実行されること。LLM/ComfyUI のロード操作が重複しないこと。
- 受付後の通信切断・再送、推論タイムアウト、生成失敗、回収失敗、キャンセル、PC 再起動を試し、履歴とジョブ ID の整合性を確認する。
- 未認証 API/画像、期限切れセッション、他オリジン、DNS rebinding、パス traversal、不正入力、過大アップロードの拒否を検証する。公開インターネットから直接到達できず、許可した VPN 経路だけから接続できることを確認する。
- スマホ対応前後の PC GUI の回帰テスト、同じワークフロー・Seed・プロンプトでの結果設定の一致、生成負荷と応答性の変化を確認する。
- Tailscale + Serve を第一候補とする。利用可能な料金・アカウント・端末・証明書の条件、Web フレームワーク、ポート、実行管理サービスの具体的な分割は実装開始時に確定する。今回の計画では依存関係を追加しない。
